RUN A SURPRISES (all from the 2.11.0 telemetry rewrite; google_cloud.py diff):
  1. Bridged log `trace` is the BARE 32-hex id, not projects/P/traces/ID.
     2.11.0 ships logs over OTLP to telemetry.googleapis.com/v1/logs (resource
     generic_task, job=service.name) instead of CloudLoggingExporter.
     So 'trace="projects/jwd-dev-5/traces/0ce77c17..."' returns ONLY the request
     log (1 entry); 'trace="0ce77c17..."' returns the 13 bridged entries;
     'trace:"0ce77c17..."' returns all 14. The request log and the bridged lines
     carry different `trace` STRINGS for the same id, so "Correlate by
     request_log" nesting on 2.11.0 is doubtful (not verified in the UI).
  2. GOOGLE_CLOUD_DEFAULT_LOG_NAME is ignored: bridged lines land under
     `adk-otel`. 2.11.0 reads GCP_DEFAULT_LOG_NAME instead.
  3. execute_tool parents invoke_agent, not call_llm (both turns).
  4. No INFO line from get_weather on the London turn: the demo tool logs only
     on failure (WARNING); the INFO tool line is fetch_forecast's (forecast prompt).

    request log spanId (9e1bd317f1dc9ea7) is POST /chat's parent, absent from
    the trace. So the tree on Cloud Run is /chat -> POST /chat -> invocation,
    one level more than page 3.4's local tree.
