# 2.5 · Sampling

*Part 2 · Collect*

> [!NOTE]
> **Why you are here.** Tracing every turn is fine in a tutorial and expensive in
> production. This page keeps a fraction of traces with the standard
> OpenTelemetry sampler, and shows why Part 3's propagation can then drop every
> trace.

A sampler decides which traces are kept. ADK installs none of its own, so the
SDK default `ParentBased(ALWAYS_ON)` applies: keep every root span, and follow
the parent's decision for child spans. Without a sampler every turn is kept, as
in [2.3](2.3-your-own-server.md). The standard environment variables change
that.

**Step 1 — Restart the server with a ratio sampler.** The sampler is read at
startup, so stop the `02` server from 2.3 (Ctrl+C) and restart it keeping half
the traces:

**Command:**

```bash
source .venv/bin/activate
export OTEL_TRACES_SAMPLER=parentbased_traceidratio
export OTEL_TRACES_SAMPLER_ARG=0.5
python examples/02_trace_server.py
```

**Step 2 — Send 20 turns.** In the second terminal, send 20 baseline turns,
save the lines, and count the turns that returned a trace id:

**Command:**

```bash
cd "$(git rev-parse --show-toplevel)/ai/adk/tracing"
source env.sh
export HOST=http://localhost:8080
export ENDPOINT=chat
./load/turns.sh baseline 20 | tee out/sampling.txt
grep -c 'trace=[0-9a-f]' out/sampling.txt
```

**Expected output** (trimmed to the first four turns and the count):

```console
baseline        turn   1  6.71s  trace=df409c07a18c3d4372d1f3e5377facd7
baseline        turn   2  5.08s  trace=—
baseline        turn   3  5.31s  trace=9b6f7f0d15f6050275e58f5b5ed167ea
baseline        turn   4  3.69s  trace=—
...
11
```

> [!IMPORTANT]
> **What it means.** Every turn answered, but 9 of the 20 print `trace=—`. The
> sampler dropped those traces at the root, so no span was recorded and the
> server had no trace id to return. Eleven out of twenty is within the noise of
> a coin flip on a small run; over thousands of turns it converges on half.

**Step 3 — Count what Cloud Trace kept.** After a minute or two of indexing,
list recent traces and keep only the ids from your 20 turns:

**Command:**

```bash
./trace/list_traces.sh 'span:invoke_agent' 10 2>/dev/null | grep -F -f <(grep -o '[0-9a-f]\{32\}' out/sampling.txt)
```

**Expected output** (trimmed to four of the eleven lines):

```console
26b1fe097ff8a6bf2d3cb23fd1dc7d64  7 spans
c7027c0814763d3251946a88ff500d56  7 spans
0ec59034c90b1a833c8790e9a972ee97  7 spans
564424705a5ce7561cfb32aa96a75677  7 spans
...
```

> [!IMPORTANT]
> **What it means.** All eleven kept traces arrived, each with all seven spans.
> The ratio sampler drops whole traces, not stray spans: the decision is made
> once at the root and inherited by the tree, which keeps a sampled trace from
> having holes.

**Step 4 — Turn the sampler off.** Stop the server (Ctrl+C), then clear the
variables so later pages keep every trace:

**Command:**

```bash
unset OTEL_TRACES_SAMPLER OTEL_TRACES_SAMPLER_ARG
```

Sampling is your main cost lever
([4.5 · Cost, retention, and content policy](../part-4/4.5-cost-retention-content.md)):
halve the sample, halve the ingestion. But the `ParentBased` half of the default
sampler can drop every trace once Part 3 turns on propagation.

## Deep dives

### Why can propagation drop every trace?

`parentbased_traceidratio` is two rules: for a root span, keep it with the
given probability; for a span with a parent, do whatever the parent decided.
Locally every trace is its own root, so the ratio is all that matters. But once
[3.4 · One trace per request](../part-3/3.4-one-trace-per-request.md) makes
ADK's spans children of an inbound request, the parent's sampling decision wins,
and if that parent arrived unsampled, ADK records nothing for the request.
Propagation can silently stop your traces from being recorded. 3.4's deep dive
reproduces that and fixes it with `OTEL_TRACES_SAMPLER=always_on`. For now, note
that a sampled-out turn still carries a trace id in its logs, an id that leads
to a trace Cloud Trace never stored.
