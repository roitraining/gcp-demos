# 2.6 · Other backends

*Part 2 · Collect*

> [!NOTE]
> **Why you are here.** The tree is plain OpenTelemetry, so Google is not the
> only place it can go. This reference page shows the one variable that sends it
> to any OTLP collector, and lists some backends that accept it.

ADK reads the standard OTLP environment variables. Set an endpoint and the SDK
adds a generic `OTLPSpanExporter` alongside whatever else is configured
(`google/adk/telemetry/setup.py:124-153`):

```bash
export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=https://your-collector:4318/v1/traces
```

| Fact | Detail |
|---|---|
| Protocol | HTTP/protobuf only (`otlp-proto-http`). The gRPC exporter is not wired in. |
| Additive | This route is added to the GCP route, not instead of it. Set `--otel_to_cloud` **and** the OTLP endpoint and the tree is exported to both: dual export. |
| Headers | Auth and other headers go through `OTEL_EXPORTER_OTLP_HEADERS`, the standard variable. |
| Content | The `gcp.vertex.agent.*` content attributes travel too; `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS` ([1.3](../part-1/1.3-attributes-and-content.md)) still governs them. |

Any OTLP backend accepts the spans. The `gen_ai.*` attributes follow the
OpenTelemetry GenAI convention, but many of ADK's attributes are
`gcp.vertex.agent.*`, which are not part of it, so check the vendor's ADK page
for how it maps them. Some backends that take OTLP:

| Backend | What it is |
|---|---|
| Phoenix (Arize) | open-source LLM tracing and evaluation; on the adk.dev integrations list |
| AgentOps | agent-run session replay and cost tracking; on the adk.dev integrations list |
| MLflow | experiment tracking with a tracing view; on the adk.dev integrations list |
| Honeycomb | general OTLP backend with strong trace querying |

Point the endpoint at the backend's OTLP collector and the same tree you sent to
Cloud Trace arrives there. This tutorial stays on the Google path; the rest of it
assumes `--otel_to_cloud`.

**Not verified.** Nothing on this page was run for this tutorial.

| Claim | Status |
|---|---|
| Spans reach a non-Google OTLP collector | Read from `google/adk/telemetry/setup.py`; not run |
| Dual export with `--otel_to_cloud` | Read from source; [2.3](2.3-your-own-server.md)'s `export-outage` adds the same extra exporter and the Google export still lands |
| Each backend renders ADK's tree | Not checked against any vendor |
