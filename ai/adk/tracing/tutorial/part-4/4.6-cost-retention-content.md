# 4.6 · Cost, retention, and content policy

*Part 4 · Consume*

> [!NOTE]
> **Why you are here.** Tracing every turn is on by default, and so is the
> prompt text on every span. This reference page covers what that costs, how
> long it lasts, and what to keep out of a span before production.

Three settings decide the bill and the risk: how many spans you keep, how big
they are, and what they contain.

## What it costs

Cloud Trace bills by **trace spans ingested**
([estimating your bills](https://docs.cloud.google.com/stackdriver/estimating-bills)).
For the current per-span rate and the free monthly allotment, see the
[Google Cloud Observability pricing](https://cloud.google.com/products/observability/pricing)
page. This tutorial quotes no figures because they change.

The count is what moves the bill. The `baseline` turn is seven spans; the
`slow-tool` turn with `TUTORIAL_CUSTOM_SPAN=1` adds one more; a server with
`FastAPIInstrumentor` adds four per request (`POST /chat`, its `http receive`,
and two `http send`) ([3.4](../part-3/3.4-one-trace-per-request.md)).
Multiply by turns per day.

| Lever | Effect on spans | Cost to you |
|---|---|---|
| Sampling ([2.5](../part-2/2.5-sampling.md)) | Keeps a fraction of traces, whole | Rare slow or failed turns may not be kept |
| Fewer instrumentors | Drops server spans | Request-level lines lose their parent span |
| No custom spans | Drops your `fetch_forecast`-style spans | The dependency's time hides inside `execute_tool` |

Sample by trace, never by span. A parent-based sampler keeps or drops the whole
tree, so every trace you keep is complete. [2.5](../part-2/2.5-sampling.md)
shows the setting and [3.4](../part-3/3.4-one-trace-per-request.md) the trap
when a caller sends an unsampled parent.

## How long it lasts

Spans in the `_Trace` bucket are kept for **30 days**
([quotas and limits](https://docs.cloud.google.com/trace/docs/quotas)). A trace
id in a support ticket stops resolving after that, and so does the span side of
a log join. If you need a turn longer, keep it somewhere you control: the
[4.3](4.3-the-failed-step.md) run record for a known failure, or BigQuery rows
for every turn ([4.5](4.5-traces-logs-metrics-rows.md)).

## How big a span can be

From the same quotas page, for spans written through the Telemetry (OTLP) API:

| Limit | Value |
|---|---|
| Attribute key | 512 bytes |
| Attribute value | 64 KiB |
| Attributes per span | 1,024 |
| Span name | 1,024 bytes |
| Events per span | 256 |

Past the attribute count, Cloud Trace keeps 1,024 chosen non-deterministically
and discards the rest. The Agent Platform
[tracing doc](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/runtime/tracing)
warns that "some attribute values might get truncated when they reach quota
limits." The attribute most likely to hit a limit is
`gcp.vertex.agent.llm_request`, which holds the whole prompt and conversation
history ([1.3](../part-1/1.3-attributes-and-content.md)). A long session can
outgrow it, so do not rely on the span as the complete record of a prompt.

## What should never be in a span

Two knobs govern content, with opposite defaults
([1.3](../part-1/1.3-attributes-and-content.md)):

| Knob | Governs | Default | Off means |
|---|---|---|---|
| `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS` | `gcp.vertex.agent.*` payload attributes on spans | on | `llm_request`, `llm_response`, `tool_call_args`, `tool_response` become `"{}"` |
| `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` | the `gen_ai.*` content log events | `NO_CONTENT` (off) | the log events are still emitted, with each message's content replaced by `<elided>` |

Treat them as a policy, written down once per environment:

| Environment | Spans | Log events | Why |
|---|---|---|---|
| Laptop, dev | on | on | You are reading prompts to debug them |
| Shared staging | off | on, to a restricted log bucket | Logs have finer access control and their own retention |
| Production with user data | off | off, or redacted first | Anyone with trace viewer access reads every prompt otherwise |

Some redaction happens regardless. ADK never writes `http_options` credentials,
`response_schema`, or `inline_data` bytes into `llm_request`
(`google/adk/telemetry/tracing.py:834-862`). And
`adk deploy agent_engine --otel_to_cloud` sets the span knob to `false` unless
your `.env` sets it (`google/adk/cli/cli_deploy.py:1281-1282`);
`adk deploy cloud_run` does not, so a Cloud Run deploy ships prompts in spans
until you turn the knob off.

> [!WARNING]
> Turning off the span knob does not remove tool arguments you put in your own
> span attributes or log lines; review those by hand.

The [reference page](../how-to-choose.md) collects the span catalog, the
correlation decisions, and what this tutorial verified.
