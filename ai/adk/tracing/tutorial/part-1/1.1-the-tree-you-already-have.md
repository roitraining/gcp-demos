# 1.1 · The tree you already have

*Part 1 · What a trace is*

> [!NOTE]
> **Why you are here.** ADK opens a span tree around every turn without any
> configuration. This page shows you that tree in the dev UI, first for a plain
> turn and then for a slow one, so you can see the shape before you learn the
> parts.

The `baseline` scenario is one weather question in a fresh session. Start the dev
UI and ask it.

**Step 1 — Start the dev UI.**

**Command:**

```bash
source env.sh
.venv/bin/adk web .
```

Open the printed URL, pick `demo_agent`, and ask **What's the weather in
London?** Then open the **Trace** tab.

**What you are looking at.** The tab draws a waterfall of the spans ADK opened
for that turn. Read from the top:

```console
invocation
└─ invoke_agent weather_agent
   ├─ call_llm
   │  ├─ generate_content gemini-3.7-flash
   │  └─ execute_tool get_weather
   └─ call_llm
      └─ generate_content gemini-3.7-flash
```

> [!IMPORTANT]
> **What it means.** Seven spans, five names, and you configured none of it. One
> turn ran the model twice — once to decide to call `get_weather`, once to phrase
> the answer — so `call_llm` and `generate_content` each appear twice.
> `execute_tool` sits under the first `call_llm`, not under `invoke_agent`: ADK
> opens the tool span while it is still inside the model turn that requested the
> call.

**Step 2 — Ask a slow question.** In the same UI, ask **What's the three-day
forecast for London?** and open its **Trace** tab. The tree has the same shape,
but the bars are not the same length:

```console
invoke_agent weather_agent          4.693s
├─ call_llm                         2.531s
│  └─ execute_tool get_forecast     0.407s
└─ call_llm                         2.161s
```

> [!IMPORTANT]
> **What it means.** On the baseline turn `execute_tool` was about a millisecond,
> lost against the two model calls. On the forecast turn `get_forecast` sleeps,
> so its bar is now hundreds of milliseconds. The tree told you *which* step got
> slower without you adding a single timer. Finding the slow step from the tree
> is what [Part 4](../part-4/index.md) does at scale.

> [!NOTE]
> Durations vary run to run because the model does, so your numbers will differ.

This tree lives only in the dev UI's memory: restart `adk web` and it is gone.
[1.2](1.2-the-raw-span.md) exports the same tree to your terminal as JSON, one
span at a time, so you can read what a span is actually made of.

## Deep dives

### Where does the dev UI keep the tree?

`adk web` installs two in-process span exporters and no cloud exporter
(`cli/dev_server.py`; `api_server.py:458-518`). One keeps the finished spans of
each session in memory, keyed by session id, which is what the **Trace** tab and
the `/dev/apps/{app}/debug/trace/session/{id}` endpoint read. Because it is an
in-memory store, it is unbounded and it does not survive a restart. Nothing
leaves the process: to send the tree anywhere you install an exporter yourself,
which is [Part 2](../part-2/index.md).
