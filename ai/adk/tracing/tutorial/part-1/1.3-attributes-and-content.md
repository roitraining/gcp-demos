# 1.3 · Attributes and content

*Part 1 · What a trace is*

> [!NOTE]
> **Why you are here.** A span's attributes hold more than timings: by default
> they hold the prompt and the model's reply. This page shows what is on a span,
> and the one variable that stops content from being stored.

Run the `baseline` scenario again:

**Command:**

```bash
source .venv/bin/activate
python examples/01_console_spans.py
```

**Expected output:** in `out/spans.json`, the first `call_llm` span (trimmed to
four attributes) holds two families of attributes side by side:

```json
{
  "name": "call_llm",
  "attributes": {
    "gen_ai.system": "gcp.vertex.agent",
    "gen_ai.request.model": "gemini-3.7-flash",
    "gcp.vertex.agent.llm_request": "{\"model\": \"gemini-3.7-flash\", \"config\": {\"system_instruction\": \"You are a concise weather assistant...\"}, \"contents\": [...]}",
    "gcp.vertex.agent.llm_response": "{...}"
  }
}
```

| family | example | what it is |
|---|---|---|
| `gen_ai.*` | `gen_ai.request.model` | The OpenTelemetry GenAI semantic convention: portable keys any GenAI backend understands. On spans, metadata only. |
| `gcp.vertex.agent.*` | `gcp.vertex.agent.llm_request` | ADK's own attributes. `llm_request` and `llm_response` hold the **full prompt and reply** as JSON. |

> [!IMPORTANT]
> **What it means.** By default a span carries the conversation, not just its
> timing. `gcp.vertex.agent.llm_request` on the London turn is about two kilobytes
> of JSON: the system instruction, the tool declarations, and the user's message.
> That is what makes the **Inputs/Outputs** tab in Cloud Trace useful later, and
> what you must think about before tracing a real user's prompts.

**👉 Turn content off.** Set `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS` to `false` and rerun:

**Command:**

```bash
export ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false
python examples/01_console_spans.py
unset ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS
```

**Expected output:** the same `call_llm` span, with the content attributes
emptied:

```json
{
  "name": "call_llm",
  "attributes": {
    "gen_ai.request.model": "gemini-3.7-flash",
    "gcp.vertex.agent.llm_request": "{}",
    "gcp.vertex.agent.llm_response": "{}"
  }
}
```

The `execute_tool` span's `gcp.vertex.agent.tool_call_args` and `tool_response`
go to `{}` the same way. The `gen_ai.*` metadata stays: you still get the model,
the timing, and the tree. You lose only the prompts and replies.

> [!IMPORTANT]
> **What it means.** The tree does not depend on content. Turn it off and you
> still trace which step ran, how long it took, and whether it failed; you just
> no longer store what the user said. This is the setting to reach for before you
> trace production traffic.

## Deep dives

### Is there a second content setting?

There are two environment variables, and they are easy to confuse because they
do different jobs and default in opposite directions.

| Variable | Governs | Default | Effect when off |
|---|---|---|---|
| `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS` | the `gcp.vertex.agent.*` payload attributes on spans (this page) | **on** | `llm_request`, `llm_response`, `tool_call_args`, `tool_response` become `"{}"` |
| `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` | the `gen_ai.*` **log events** (Part 3), not these attributes | `NO_CONTENT` (off) | the log events are still emitted, with each message's content replaced by `<elided>` |

So out of the box, span attributes carry content and the log events carry only
`<elided>` (`google/adk/telemetry/context.py:46`, `:93-112`;
`google/adk/telemetry/_stable_semconv.py:50-56`). A few payloads are always
redacted regardless of either variable: credentials in `http_options`, the
`response_schema`, and any `inline_data`
(`google/adk/telemetry/tracing.py:834-862`). And
`adk deploy agent_engine --otel_to_cloud` sets
`ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS` to `false` for you; `adk deploy
cloud_run` does not (`google/adk/cli/cli_deploy.py:1274-1282`).
