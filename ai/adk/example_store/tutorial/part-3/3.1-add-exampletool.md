# 3.1 · Add ExampleTool

*Part 3 · Attach the store to the agent*

> [!NOTE]
> **Why you are here.** The agent in Part 1 had no examples. This page runs a
> second agent that differs only by `ExampleTool`, and asks the same four
> questions.

[agents/with_examples/agent.py](../../agents/with_examples/agent.py) wraps the
store in ADK's `VertexAiExampleStore` provider and hands it to `ExampleTool`:

```python
store = VertexAiExampleStore(os.environ["EXAMPLE_STORE_NAME"])

root_agent = LlmAgent(
    name="order_support",
    model=MODEL,
    instruction=INSTRUCTION,
    tools=[get_order_status, ExampleTool(store)],
    before_model_callback=log_examples,
)
```

The instruction, model, and order tool are the same as in Part 1.

**Step 1 — Ask the four questions again.**

**Command:**

```bash
.venv/bin/adk run agents/with_examples "Where is order 4417?"
.venv/bin/adk run agents/with_examples "Where's my order?"
.venv/bin/adk run agents/with_examples "I want a refund for order 5521."
.venv/bin/adk run agents/with_examples "What's a good recipe for pancakes?"
```

**Expected output:** trimmed to the agent's lines; the order question's second
example list is cut.

> [!IMPORTANT]
> **What it means.** All four replies now match the store's wording, word for
> word, from examples alone.
>
> | Intent | Part 1 | Now |
> |---|---|---|
> | Order status | Free-form, with bold markup | `Order 4417: shipped, arrives Tuesday.` |
> | Missing order ID | Asked for the ID | Asks in the stored words |
> | Refund | Called the tool, invented a process | The policy sentence, no tool call |
> | Off-topic | Wrote the recipe | One sentence back to orders |
>
> The example lists match the kept rows from 2.2, in the same order. Each
> request carried several examples for other intents, and the model still
> followed the closest one.

> [!WARNING]
> If a command prints `Error: 500 Internal error encountered.`, the store
> search failed; run it again. See
> [Why do some searches fail?](../part-2/2.2-search-the-store.md#why-do-some-searches-fail)

The order question logged two example lists. Page 3.2 explains why.

## Deep dives

### What does Gemini receive?

ADK appends the matches to the system instruction as text. Captured for the
order question and trimmed to its first example:

````console
<EXAMPLES>
Begin few-shot
The following are examples of user queries and model responses using the available tools.

EXAMPLE 1:
Begin example
[user]
Where is order 2210?
[model]
```tool_code
get_order_status(order_id='2210')
```
[user]
```tool_outputs
{'will_continue': None, 'scheduling': None, 'parts': None, 'id': None, 'name': 'get_order_status', 'response': {'status': 'shipped', 'order_id': '2210', 'eta': 'Monday'}}
```
[model]
Order 2210: shipped, arrives Monday.
End example

End few-shot
<EXAMPLES>
````

The tool call is shown as Python inside a `tool_code` fence. For models whose
name contains `gemini-2`, ADK uses a plain fence instead
(`google/adk/examples/example_util.py:62`). The tool output is the response
object's internal fields, empty ones included.

### Does the model call ExampleTool?

No. `ExampleTool` declares no function, so Gemini never sees it as a tool. No
`example_tool` call appears in any run. It only edits the request before ADK
sends it.
