# 2.1 · Load the examples

*Part 2 · Fill and search the store*

> [!NOTE]
> **Why you are here.** The store from Setup is empty. This page loads eight
> examples into it, two for each intent from Part 1.

Check that `.env` now holds the `EXAMPLE_STORE_NAME=...` line from Setup. The
store scripts read it from there.

**Step 1 — Read one example.**

The examples live in [store/examples.py](../../store/examples.py). This is
the first one, written out in full:

```python
{
    "search_key": "Where is order 2210?",
    "contents_example": {
        "contents": [{"role": "user", "parts": [{"text": "Where is order 2210?"}]}],
        "expected_contents": [
            {"content": {"role": "model", "parts": [{"function_call": {
                "name": "get_order_status", "args": {"order_id": "2210"}}}]}},
            {"content": {"role": "user", "parts": [{"function_response": {
                "name": "get_order_status",
                "response": {"order_id": "2210", "status": "shipped", "eta": "Monday"}}}]}},
            {"content": {"role": "model", "parts": [{"text": "Order 2210: shipped, arrives Monday."}]}},
        ],
    },
}
```

> [!IMPORTANT]
> **What you are looking at.**
>
> | field | value | what it is |
> |---|---|---|
> | `search_key` | `Where is order 2210?` | The text the store embeds. A search matches against this, nothing else. |
> | `contents` | the user's message | The conversation so far when the example starts. |
> | `expected_contents` | tool call, tool response, reply | What the model should do next, step by step. |
>
> The other seven examples have the same shape. The examples that need no tool
> have a single reply step. The order IDs in the examples differ from the ones
> you ask about, so the agent copies the pattern, not the answer.

**Step 2 — Load them.**

[store/load_examples.py](../../store/load_examples.py) sends the examples in
batches of five, the most one upsert call accepts.

**Command:**

```bash
.venv/bin/python store/load_examples.py
```

**Expected output:**

```console
stored: Where is order 2210?
stored: Has my order 1875 shipped yet?
stored: Where's my package?
stored: My order hasn't arrived and I'm getting worried.
stored: I want a refund for order 6032.
stored: Can I get my money back? The item arrived broken.
stored: What's the weather like today?
stored: Can you recommend a good laptop?
```

> [!IMPORTANT]
> **What it means.** All eight are stored, and the store has embedded each
> search key. `overwrite=True` makes the script safe to rerun: an example
> already in the store is replaced, not added twice.

Page 2.2 searches the store with the four questions from Part 1.

## Deep dives

### Why is the search key the user's message?

ADK searches with the latest user message, so stored keys work best when they
read like user messages too. The store can also build the key itself from the
conversation (`search_key_generation_method`), but an explicit key shows you
exactly what gets matched.
