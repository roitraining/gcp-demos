# 3.2 · Volume and shape

*Part 3 · Consume: signals from histograms*

> [!NOTE]
> **Why you are here.** Scenario `multi-city`: is repeated work driving latency and
> consumption? This page reads turns per minute and work per turn, then reads the
> bucket distribution behind the mean.

The `multi-city` scenario names three cities in one prompt on a quarter of the
turns, so those turns call the tool three times. That difference should show up
two ways: as a higher mean of tool calls per turn, and as a second population in
the `tool_calls` bucket distribution. Queries live in
[queries/volume.promql](../../queries/volume.promql).

**Step 1 — Restart the server under this page's name.** In the server terminal,
stop the server with `Ctrl+C` and start it again as `adk-metrics-3-2`, the
`job` every query below filters on.

**Command:**

```bash
source env.sh
export OTEL_SERVICE_NAME=adk-metrics-3-2
.venv/bin/adk web --otel_to_cloud ./
```

**Step 2 — Drive the scenario.** In the second terminal:

**Command:**

```bash
load/turns.sh multi-city 40
```

**Expected output** (turns 4 to 37 trimmed):

```console
multi-city      turn   1  http=200  3.56s
multi-city      turn   2  http=200  2.91s
multi-city      turn   3  http=200  4.07s
...
multi-city      turn  38  http=200  2.87s
multi-city      turn  39  http=200  3.01s
multi-city      turn  40  http=200  2.87s
waiting 10s for the final export interval...
good to go — the series are in Cloud Monitoring
```

**Step 3 — Read turns per minute and work per turn.** The `_count` of
`invoke_agent.duration` is the turn counter; `rate()` over it times 60 is turns
per minute.

**Command:**

```bash
source env.sh
export TOKEN=$(gcloud auth application-default print-access-token)
export QUERY='sum(rate({"gen_ai.invoke_agent.duration_count", job="adk-metrics-3-2"}[10m])) * 60'
curl -s -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "query=$QUERY" \
  "https://monitoring.googleapis.com/v1/projects/$PROJECT_ID/location/global/prometheus/api/v1/query"
```

**Expected output:**

```console
{"status":"success","data":{"resultType":"vector","result":[{"metric":{},"value":[1791021745.948,"4"]}]}}
```

For the mean work per turn, divide the `_sum` of `inference_calls` and of
`tool_calls` by their `_count`. Model calls per turn first:

**Command:**

```bash
export QUERY='sum(rate({"gen_ai.invoke_agent.inference_calls_sum", job="adk-metrics-3-2"}[10m])) / sum(rate({"gen_ai.invoke_agent.inference_calls_count", job="adk-metrics-3-2"}[10m]))'
curl -s -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "query=$QUERY" \
  "https://monitoring.googleapis.com/v1/projects/$PROJECT_ID/location/global/prometheus/api/v1/query"
```

**Expected output:**

```console
{"status":"success","data":{"resultType":"vector","result":[{"metric":{},"value":[1791021746.232,"2"]}]}}
```

Then tool calls per turn:

**Command:**

```bash
export QUERY='sum(rate({"gen_ai.invoke_agent.tool_calls_sum", job="adk-metrics-3-2"}[10m])) / sum(rate({"gen_ai.invoke_agent.tool_calls_count", job="adk-metrics-3-2"}[10m]))'
curl -s -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "query=$QUERY" \
  "https://monitoring.googleapis.com/v1/projects/$PROJECT_ID/location/global/prometheus/api/v1/query"
```

**Expected output:**

```console
{"status":"success","data":{"resultType":"vector","result":[{"metric":{},"value":[1791021746.487,"1.5"]}]}}
```

**Step 4 — Read the two populations.** The mean hides the mix. Histogram buckets
in PromQL are cumulative: each `le` bucket counts every turn at or below its
bound, since the server started. `increase()` over the window keeps only this
run, and subtracting each bucket from the next gives the turns in each range.

**Command:**

```bash
export QUERY='sum by (le) (increase({"gen_ai.invoke_agent.tool_calls_bucket", job="adk-metrics-3-2"}[10m]))'
curl -s -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "query=$QUERY" \
  "https://monitoring.googleapis.com/v1/projects/$PROJECT_ID/location/global/prometheus/api/v1/query"
```

**Expected output** (buckets above `le="4"` trimmed; they all read 40):

```console
{"status":"success","data":{"resultType":"vector","result":[{"metric":{"le":"0"},"value":[1791021746.763,"0"]},{"metric":{"le":"1"},"value":[1791021746.763,"30"]},{"metric":{"le":"2"},"value":[1791021746.763,"30"]},{"metric":{"le":"3"},"value":[1791021746.763,"40"]},{"metric":{"le":"4"},"value":[1791021746.763,"40"]},...]}}
```

> [!IMPORTANT]
> **What it means.** Tool calls per turn rose to 1.5, above the baseline's 1, but
> model calls per turn held at 2: the model asks for all three cities in one
> response. The buckets say why the mean moved: 30 turns at `le="1"` and 10 more
> between `le="2"` and `le="3"`, two populations, not one shifted average. The
> three-city turns add tool calls, not model calls.

3.3 turns from how much work to how much of it failed.
