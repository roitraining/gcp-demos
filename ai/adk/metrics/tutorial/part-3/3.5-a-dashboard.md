# 3.5 · A dashboard

*Part 3 · Consume — signals from histograms*

> [!NOTE]
> **Why you are here.** You have answered the four questions with four queries.
> This page puts those same queries on one dashboard so you read them at a glance
> instead of pasting `curl` commands.

The four signals from 3.1 through 3.4 become four widgets: latency percentiles,
turns per minute, the tool error ratio, and tokens per minute by type. They are
already written as PromQL, so the dashboard is those queries in a JSON config.
The panel set mirrors a well-known ADK dashboard so it reads as a standard board.
Run `baseline` under load first so every widget has data.

**Step 1 — Drive the scenario.**

**Command:**

```bash
export TURNS_SERVER=http://localhost:8000
load/turns.sh baseline 30
```

**Expected output:**

```console
NEEDS-RUN: load/turns.sh baseline 30 — 30 London turns, all HTTP 200
```

**Step 2 — Create the dashboard.** The config is
[queries/dashboard.json](../../queries/dashboard.json): one PromQL widget per
signal, each holding the query from its 3.x page.

**Command:**

```bash
export PROJECT=jwd-gcp-demos
gcloud monitoring dashboards create \
  --project="$PROJECT" \
  --config-from-file=queries/dashboard.json
```

**Expected output:** the created dashboard's resource name.

```console
NEEDS-RUN: gcloud monitoring dashboards create — Created [projects/jwd-gcp-demos/dashboards/...]
```

> [!IMPORTANT]
> **What it means.** The four operator questions now live on one board that
> refreshes itself. Nothing new is measured; the widgets read the same six
> histograms the `curl` reads did. A dashboard is where the queries you trust go
> to be read without retyping.

**Step 3 — View it.** Open **Monitoring → Dashboards** in the Console and select
the new board. Confirm every widget renders data from the `baseline` run. This is
a browser step, described here, not captured.

```console
NEEDS-RUN: dashboard rendered — four widgets (latency p50/p95, turns/min, tool error ratio, tokens/min by type) showing baseline data
```

**Step 4 — Tear down.** Delete the dashboard so it does not linger. Take its id
from the resource name in Step 2.

**Command:**

```bash
export PROJECT=jwd-gcp-demos
export DASHBOARD_ID=NEEDS-RUN
gcloud monitoring dashboards delete \
  "projects/$PROJECT/dashboards/$DASHBOARD_ID" \
  --project="$PROJECT" \
  --quiet
```

3.6 promotes one of these widgets from something you watch to something that
pages you.
