# 3.5 · A dashboard

*Part 3 · Consume: signals from histograms*

> [!NOTE]
> **Why you are here.** Scenario `baseline`: can I answer the four questions
> without writing a query? This page puts the queries from 3.1 to 3.4 on one
> dashboard so you read them at a glance.

The config, [queries/dashboard.json](../../queries/dashboard.json), holds eight
PromQL widgets that read four histograms: turn and tool latency, model call
duration, turns and model calls per minute, the tool error ratio, and tokens per
minute and per call. Run `baseline` under load first so the widgets have data.

Keep the 3.1 server running, and wait 5 minutes after the last page's load.

**Step 1 — Drive the scenario.**

**Command:**

```bash
load/turns.sh baseline 30
```

**Expected output** (turns 4 to 27 trimmed):

```console
baseline        turn   1  http=200  4.45s
baseline        turn   2  http=200  4.00s
baseline        turn   3  http=200  3.77s
...
baseline        turn  28  http=200  3.33s
baseline        turn  29  http=200  3.50s
baseline        turn  30  http=200  3.74s
waiting 10s for the final export interval...
good to go — the series are in Cloud Monitoring
```

**Step 2 — Create the dashboard.** `--format='value(name)'` prints only the new
dashboard's resource name, which `DASHBOARD_ID` keeps for the teardown.

**Command:**

```bash
source env.sh
export DASHBOARD_ID=$(gcloud monitoring dashboards create \
  --project="$PROJECT_ID" \
  --config-from-file=queries/dashboard.json \
  --format='value(name)')
echo "$DASHBOARD_ID"
```

**Expected output:** the dashboard's resource name, with your project number and
a generated id.

```console
Created [5418276a-0a58-4bc6-8e59-5d02d969feeb].
projects/376236993953/dashboards/5418276a-0a58-4bc6-8e59-5d02d969feeb
```

> [!IMPORTANT]
> **What it means.** The operational questions now live on one board that
> refreshes itself. Nothing new is measured; the widgets read the same histograms
> the `curl` reads did. A dashboard is where the queries you trust go to be read
> without retyping.

**Step 3 — View it.** This is a browser step, described here, not captured.

- Open **Monitoring → Dashboards**.
- Select **ADK agent metrics (tutorial 3.5)**.
- Set the time range to **1 hour**.

Eight widgets fill with the `baseline` run. The same queries, read through the
API right after Step 2, gave a turn p95 of 6.2 s, 6 turns and 12 model calls per
minute, about 4,300 input and 180 output tokens per minute, and 357 input tokens
per model call. `get_weather` is the only tool line, near 0.01 s. The tool error
ratio reads 0 because 3.3's failed series still exists on this server; on a
server that has never seen a failure, that widget stays empty under `baseline`.

**Step 4 — Tear down.** Delete the dashboard so it does not linger.

**Command:**

```bash
gcloud monitoring dashboards delete "$DASHBOARD_ID" \
  --project="$PROJECT_ID" \
  --quiet
```

**Expected output:**

```console
Deleted dashboard [5418276a-0a58-4bc6-8e59-5d02d969feeb].
```

3.6 promotes one of these widgets from something you watch to something that
opens an incident.
