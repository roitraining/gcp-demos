# 3.5 · A dashboard

*Part 3 · Consume: signals from histograms*

> [!NOTE]
> **Why you are here.** Scenario `baseline`: can I answer the four questions
> without writing a query? This page puts the queries from 3.1 to 3.4 on one
> dashboard so you read them at a glance.

The config, [queries/dashboard.json](../../queries/dashboard.json), holds eight
PromQL widgets that read four histograms: turn and tool latency, model call
duration, turns and model calls per minute, the tool error ratio, and tokens per
minute and per call. Run `baseline` under load first so the widgets have data.

**Step 1 — Restart the server under this page's name.** In the server terminal,
stop the server with `Ctrl+C` and start it again as `adk-metrics-3-5`, the
`job` every widget on the dashboard filters on.

**Command:**

```bash
source env.sh
export OTEL_SERVICE_NAME=adk-metrics-3-5
.venv/bin/adk web --otel_to_cloud ./
```

**Step 2 — Drive the scenario.** In the second terminal:

**Command:**

```bash
load/turns.sh baseline 30
```

**Expected output** (turns 4 to 27 trimmed):

```console
baseline        turn   1  http=200  5.17s
baseline        turn   2  http=200  3.18s
baseline        turn   3  http=200  3.06s
...
baseline        turn  28  http=200  2.85s
baseline        turn  29  http=200  2.75s
baseline        turn  30  http=200  2.97s
waiting 10s for the final export interval...
good to go — the series are in Cloud Monitoring
```

**Step 3 — Create the dashboard.** `--format='value(name)'` prints only the new
dashboard's resource name, which `DASHBOARD_ID` keeps for the teardown.

**Command:**

```bash
source env.sh
export DASHBOARD_ID=$(gcloud monitoring dashboards create \
  --project="$PROJECT_ID" \
  --config-from-file=queries/dashboard.json \
  --format='value(name)')
echo "$DASHBOARD_ID"
```

**Expected output:** the dashboard's resource name, with your project number and
a generated id.

```console
Created [4533b665-bd4a-4c6a-83a8-0ba16d113d82].
projects/240659336105/dashboards/4533b665-bd4a-4c6a-83a8-0ba16d113d82
```

> [!IMPORTANT]
> **What it means.** The operational questions now live on one board that
> refreshes itself. Nothing new is measured; the widgets read the same histograms
> the `curl` reads did. A dashboard is where the queries you trust go to be read
> without retyping.

**Step 4 — View it.** This is a browser step, described here, not captured.

- Open **Monitoring → Dashboards**.
- Select **ADK agent metrics (tutorial 3.5)**.
- Set the time range to **1 hour**.

Eight widgets fill with the `baseline` run. The same queries, read through the
API a minute after the load ended, gave a turn p95 of 5.9 s, 3 turns and 6 model
calls per minute, about 2,100 input and 90 output tokens per minute, and 357
input tokens per model call. `get_weather` is the only tool line, near 0.01 s.
The tool error ratio widget is empty: this server has never seen a failure, and
the widget would read 0 only once a failed series exists, as it did after 3.3.

**Step 5 — Tear down.** Delete the dashboard so it does not linger.

**Command:**

```bash
gcloud monitoring dashboards delete "$DASHBOARD_ID" \
  --project="$PROJECT_ID" \
  --quiet
```

**Expected output:**

```console
Deleted dashboard [4533b665-bd4a-4c6a-83a8-0ba16d113d82].
```

3.6 promotes one of these widgets from something you watch to something that
opens an incident.
