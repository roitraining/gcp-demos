# 3.6 · An alert

*Part 3 · Consume — signals from histograms*

> [!NOTE]
> **Why you are here.** A dashboard tells you when you look; an alert tells you
> when you are not looking. This page turns the tool error ratio from 3.3 into a
> policy, then fails enough lookups to open a real incident.

The signal is the tool error ratio from [queries/errors.promql](../../queries/errors.promql):
failed tool calls over all tool calls. The policy fires when that ratio stays
above 20% for five minutes. You create it from a JSON config, then drive
`unknown-city` at about half Atlantis to push the ratio over threshold and open an
incident.

**Step 1 — Create the alert policy.** The config is
[queries/alert-policy.json](../../queries/alert-policy.json): a PromQL condition
on the tool error ratio, threshold 0.2, duration 5 minutes.

**Command:**

```bash
export PROJECT=jwd-gcp-demos
gcloud alpha monitoring policies create \
  --project="$PROJECT" \
  --policy-from-file=queries/alert-policy.json
```

**Expected output:** the created policy's name.

```console
NEEDS-RUN: gcloud monitoring policies create — Created alert policy [projects/jwd-gcp-demos/alertPolicies/...]
```

**Step 2 — Trigger it.** Fire `unknown-city` long enough to hold the ratio above
20% for the five-minute window.

**Command:**

```bash
export TURNS_SERVER=http://localhost:8000
load/turns.sh unknown-city 120
```

**Expected output:**

```console
NEEDS-RUN: load/turns.sh unknown-city 120 — sustained ~50% Atlantis to hold the ratio over threshold
```

**Step 3 — Capture the incident.** Read the open incidents for the policy, or open
**Monitoring → Alerting** in the Console to see it.

**Command:**

```bash
export PROJECT=jwd-gcp-demos
gcloud alpha monitoring policies list \
  --project="$PROJECT" \
  --filter='displayName~"tool error"'
```

**Expected output:**

```console
NEEDS-RUN: opened incident on the tool error ratio policy — condition, threshold 0.2, observed value over 5 min
```

> [!IMPORTANT]
> **What it means.** The same ratio you read once by hand in 3.3 now watches
> itself and pages when it breaches. Note what it does not know: this fires on
> tool failures, not on task failures, so it would page for the recovered
> Atlantis turns even though every user got an answer. What to alert on when a
> failed tool is not a failed task is exactly what 3.7 addresses.

**Step 4 — Tear down.** Delete the policy so it stops evaluating. Take its id from
Step 1.

**Command:**

```bash
export PROJECT=jwd-gcp-demos
export POLICY_ID=NEEDS-RUN
gcloud alpha monitoring policies delete \
  "projects/$PROJECT/alertPolicies/$POLICY_ID" \
  --project="$PROJECT" \
  --quiet
```

3.7 measures the task, not the tool, and alerts on the number that actually
matters.
