# 3.6 · An alert

*Part 3 · Consume: signals from histograms*

> [!NOTE]
> **Why you are here.** Scenario `unknown-city`: would this have opened an
> incident? This page turns the tool error ratio from 3.3 into an alert policy,
> then fails enough lookups to open a real incident.

The signal is the tool error ratio from [queries/errors.promql](../../queries/errors.promql):
failed tool calls over all tool calls. The policy fires when that ratio stays
above 20% for five minutes. It has no notification channel, so it opens an
incident without notifying anyone.

Keep the 3.1 server running, and wait 5 minutes after the last page's load.

**Step 1 — Create the alert policy.** The config is
[queries/alert-policy.json](../../queries/alert-policy.json): a PromQL condition
on the tool error ratio, threshold 0.2, duration 5 minutes. `POLICY_ID` keeps the
new policy's name for the teardown.

**Command:**

```bash
source env.sh
export POLICY_ID=$(gcloud monitoring policies create \
  --project="$PROJECT_ID" \
  --policy-from-file=queries/alert-policy.json \
  --format='value(name)')
echo "$POLICY_ID"
```

**Expected output:** the policy's resource name, with your project number and a
generated id.

```console
Created alert policy [projects/jwd-gcp-demos/alertPolicies/9451112055554235715].
projects/jwd-gcp-demos/alertPolicies/9451112055554235715
```

**Step 2 — Trigger it.** Fire `unknown-city` long enough to hold the ratio above
20% for the five-minute window. The load takes about 8 minutes.

**Command:**

```bash
load/turns.sh unknown-city 120
```

**Expected output** (turns 4 to 117 trimmed):

```console
unknown-city    turn   1  http=200  4.29s
unknown-city    turn   2  http=200  3.82s
unknown-city    turn   3  http=200  3.70s
...
unknown-city    turn 118  http=200  3.78s
unknown-city    turn 119  http=200  3.23s
unknown-city    turn 120  http=200  3.56s
waiting 10s for the final export interval...
good to go — the series are in Cloud Monitoring
```

**Step 3 — Read the incident.** The incident opened about 8 minutes after the
policy was created, near the end of the load; if the list is empty, wait a minute
and check again. List the open alerts in the project:

**Command:**

```bash
curl -s -G \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  --data-urlencode 'filter=state="OPEN"' \
  "https://monitoring.googleapis.com/v3/projects/$PROJECT_ID/alerts"
```

**Expected output** (indented, and trimmed to the fields that identify the incident):

```console
{
  "alerts": [
    {
      "name": "projects/jwd-gcp-demos/alerts/0.oddpcv1g0ia7",
      "state": "OPEN",
      "openTime": "2026-10-03T03:24:48Z",
      "metric": {
        "labels": { "value": "0.4983269111253408" },
        "type": "prometheus.googleapis.com/gen_ai.execute_tool.duration/histogram"
      },
      "policy": {
        "name": "projects/jwd-gcp-demos/alertPolicies/9451112055554235715",
        "displayName": "ADK tool error ratio > 20% (tutorial 3.6)"
      }
    }
  ],
  "totalSize": 1
}
```

In the Console, the same incident is under **Monitoring → Alerting → Incidents**.

> [!IMPORTANT]
> **What it means.** The same ratio you read once by hand in 3.3 now watches
> itself and opens an incident when it breaches. Note what it does not know: it
> fires on any failing dependency, including turns the agent recovers from. The
> Atlantis users got no weather, but neither this ratio nor the invocation ratio
> says whether the task was done. 3.7 measures that.

**Step 4 — Tear down.** Delete the policy so it stops evaluating.

**Command:**

```bash
gcloud monitoring policies delete "$POLICY_ID" \
  --project="$PROJECT_ID" \
  --quiet
```

**Expected output:**

```console
Deleted policy [9451112055554235715].
```

3.7 measures the task, not the tool.
