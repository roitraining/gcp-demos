# 3.3 · Errors

*Part 3 · Consume: signals from histograms*

> [!NOTE]
> **Why you are here.** Scenario `unknown-city`: did a dependency failure become a
> user-visible failure? This page reads the tool error ratio and the invocation
> error ratio side by side on the same run.

The `unknown-city` scenario asks half the turns about Atlantis, which `get_weather`
cannot find. The failed lookup stamps `error.type=lookup_failed` on the tool
metric ([1.3](../part-1/1.3-attributes-and-cardinality.md);
`demo_agent/agent.py:107-110`), so the tool error ratio reads about the Atlantis
share. The invocation recovers and answers. Queries live in
[queries/errors.promql](../../queries/errors.promql).

**Step 1 — Restart the server under this page's name.** In the server terminal,
stop the server with `Ctrl+C` and start it again as `adk-metrics-3-3`, the
`job` every query below filters on.

**Command:**

```bash
source env.sh
export OTEL_SERVICE_NAME=adk-metrics-3-3
.venv/bin/adk web --otel_to_cloud ./
```

**Step 2 — Drive the scenario.** In the second terminal:

**Command:**

```bash
load/turns.sh unknown-city 40
```

**Expected output** (turns 4 to 37 trimmed):

```console
unknown-city    turn   1  http=200  4.22s
unknown-city    turn   2  http=200  2.65s
unknown-city    turn   3  http=200  4.03s
...
unknown-city    turn  38  http=200  3.48s
unknown-city    turn  39  http=200  2.81s
unknown-city    turn  40  http=200  2.53s
waiting 10s for the final export interval...
good to go — the series are in Cloud Monitoring
```

**Step 3 — Read the tool error ratio.** The ratio is failed tool calls (those
carrying `error.type`) over all tool calls.

**Command:**

```bash
source env.sh
export TOKEN=$(gcloud auth application-default print-access-token)
export QUERY='sum(rate({"gen_ai.execute_tool.duration_count", job="adk-metrics-3-3", "error.type"=~".+"}[10m])) / sum(rate({"gen_ai.execute_tool.duration_count", job="adk-metrics-3-3"}[10m]))'
curl -s -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "query=$QUERY" \
  "https://monitoring.googleapis.com/v1/projects/$PROJECT_ID/location/global/prometheus/api/v1/query"
```

**Expected output:**

```console
{"status":"success","data":{"resultType":"vector","result":[{"metric":{},"value":[1791021750.332,"0.5"]}]}}
```

**Step 4 — Read the invocation error ratio.** Same shape, on
`invoke_agent.duration`. With no failed invocation the numerator has no series at
all, and a ratio over no series returns no data rather than 0. `or vector(0)`
turns that empty result into 0.

**Command:**

```bash
export QUERY='(sum(rate({"gen_ai.invoke_agent.duration_count", job="adk-metrics-3-3", "error.type"=~".+"}[10m])) or vector(0)) / sum(rate({"gen_ai.invoke_agent.duration_count", job="adk-metrics-3-3"}[10m]))'
curl -s -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "query=$QUERY" \
  "https://monitoring.googleapis.com/v1/projects/$PROJECT_ID/location/global/prometheus/api/v1/query"
```

**Expected output:**

```console
{"status":"success","data":{"resultType":"vector","result":[{"metric":{},"value":[1791021750.745,"0"]}]}}
```

> [!IMPORTANT]
> **What it means.** The tool ratio reads 0.5 and the invocation ratio reads 0, on
> one run. Without `or vector(0)` the invocation query returns `"result":[]`, no
> data, which here means zero. The dependency failed half the time and the agent
> recovered every time, and neither number tells you whether the user got
> weather. An answer of "I do not have data for Atlantis" is a successful
> invocation and a failed task; no framework metric can see that gap.

3.4 turns from failures to cost, and 3.7 comes back to the gap this page opened
with a custom counter.
