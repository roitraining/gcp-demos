# 3.3 · Errors

*Part 3 · Consume — signals from histograms*

> [!NOTE]
> **Why you are here.** A failed tool and a failed turn are different facts. This
> page reads the tool error ratio and the invocation error ratio side by side and
> finds the first high, the second zero, on the same run.

The `unknown-city` scenario asks half the turns about Atlantis, which `get_weather`
cannot find. The failed lookup stamps `error.type=lookup_failed` on the tool
metric (1.3), so the tool error ratio reads about the Atlantis share. The
invocation recovers and answers, so its error ratio reads zero. Both ratios come
from PromQL over `curl`; queries live in
[queries/errors.promql](../../queries/errors.promql).

**Step 1 — Drive the scenario.**

**Command:**

```bash
export TURNS_SERVER=http://localhost:8000
load/turns.sh unknown-city 40
```

**Expected output:**

```console
NEEDS-RUN: load/turns.sh unknown-city 40 — 40 lines, about half asking for Atlantis, all HTTP 200
```

**Step 2 — Read the tool error ratio.** The ratio is failed tool calls (those
carrying `error.type`) over all tool calls:

```
sum(rate({"gen_ai.execute_tool.duration_count", "error.type"=~".+"}[5m]))
  /
sum(rate({"gen_ai.execute_tool.duration_count"}[5m]))
```

**Command:**

```bash
export PROJECT=jwd-gcp-demos
export TOKEN=$(gcloud auth application-default print-access-token)
export QUERY='sum(rate({"gen_ai.execute_tool.duration_count", "error.type"=~".+"}[5m])) / sum(rate({"gen_ai.execute_tool.duration_count"}[5m]))'
curl -s -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "query=$QUERY" \
  "https://monitoring.googleapis.com/v1/projects/$PROJECT/location/global/prometheus/api/v1/query"
```

**Expected output:**

```console
NEEDS-RUN: PromQL tool error ratio — unknown-city run; reads about 0.5, the Atlantis share
```

**Step 3 — Read the invocation error ratio.** Same shape, on
`invoke_agent.duration`:

**Command:**

```bash
export QUERY='sum(rate({"gen_ai.invoke_agent.duration_count", "error.type"=~".+"}[5m])) / sum(rate({"gen_ai.invoke_agent.duration_count"}[5m]))'
curl -s -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "query=$QUERY" \
  "https://monitoring.googleapis.com/v1/projects/$PROJECT/location/global/prometheus/api/v1/query"
```

**Expected output:**

```console
NEEDS-RUN: PromQL invocation error ratio — unknown-city run; reads 0
```

> [!IMPORTANT]
> **What it means.** The tool ratio reads about 0.5 and the invocation ratio
> reads 0, on one run. The dependency failed half the time, the agent recovered
> every time, and neither number tells you whether the user got weather. The
> agent answering with "I do not have data for Atlantis" is a successful
> invocation and a failed task. No framework metric can see that gap, because
> success here is defined by the turn completing, not by the task being done.

3.4 turns from failures to cost, and 3.7 comes back to close the gap this page
opened with a custom counter.
