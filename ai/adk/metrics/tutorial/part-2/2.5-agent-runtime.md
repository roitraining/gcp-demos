# 2.5 · Agent Runtime

*Part 2 · Collect*

> [!NOTE]
> **Why you are here.** Cloud Run runs a long-lived process with a background
> export thread. Agent Runtime does not: it exports on the request lifecycle
> instead. This page deploys there and checks whether metrics surface at all.

Agent Runtime installs a `_RequestDrivenMetricReader` rather than the periodic
reader. When `GOOGLE_CLOUD_AGENT_ENGINE_ID` is set, ADK swaps the background
export thread for one that collects and flushes on the request lifecycle, so
there is no 5 s daemon. Whether metrics reach Cloud Monitoring through that path
is the open question this page answers with a real run; the logging tutorial found
a negative for logs and traces on Agent Runtime, and metrics use a different
reader, so the result could differ.

**Step 1 — Deploy to Agent Runtime with the flag.**

**Command:**

```bash
.venv/bin/adk deploy agent_engine \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --otel_to_cloud \
  ./demo_agent
```

Note the resource name it prints; that sets `GOOGLE_CLOUD_AGENT_ENGINE_ID` inside
the runtime.

**Step 2 — Drive turns.** Agent Runtime is not an HTTP server you can point
`load/turns.sh` at; you send turns through the Agent Engine SDK (or the
`gcloud` query surface) against the deployed resource name from Step 1. Fire
about twenty baseline turns.

**Command:**

```console
NEEDS-RUN: invoke the deployed Agent Runtime ~20 times with "What's the weather in London?" through the Agent Engine SDK for the resource from Step 1 — record the exact call used and that all twenty are answered
```

**Step 3 — Read the series back.** Wait, then query the token count for this run.

**Command:**

```bash
curl -s \
  "https://monitoring.googleapis.com/v1/projects/${PROJECT_ID}/location/global/prometheus/api/v1/query" \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  --data-urlencode 'query=count ({"gen_ai.client.token.usage_count"})'
```

**Expected output** — the result decides the page:

```console
NEEDS-RUN: PromQL count ({"gen_ai.client.token.usage_count"}) after the Agent Runtime run — RECORD THE OUTCOME: either new points from the request-driven reader (positive) OR no new points in the window (documented negative, like logs/traces in the logging tutorial). State whichever is true.
```

> [!IMPORTANT]
> **What it means.** This page reports whatever the run shows, positive or
> negative. If points arrive, the request-driven reader exports metrics and the
> pipeline is the same six series as every other route. If none do, that is the
> documented result: on Agent Runtime, prefer Cloud Run
> ([2.3](2.3-api-server-and-cloud-run.md)) or your own server
> ([2.4](2.4-your-own-server.md)) when you need these metrics, until the runtime's
> metric export is confirmed.

**Step 4 — Tear down.**

**Command:**

```bash
.venv/bin/adk delete agent_engine \
  --project="$PROJECT_ID" --region="$REGION" ./demo_agent
```

[2.6](2.6-other-backends.md) points the same metrics at a non-Google backend, for
reference.
