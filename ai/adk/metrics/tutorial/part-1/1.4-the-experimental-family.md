# 1.4 · The experimental family

*Part 1 · What a metric is*

> [!NOTE]
> **Why you are here.** Scenario `baseline`: how many tokens did the whole turn
> use? The six metrics so far are recorded per model call, per tool call, or per
> agent turn, and the family that sums tokens over the turn is off by default.

The `baseline` scenario again, one London turn, but with one environment
variable set. `adk.experimental.*` metrics stay silent unless
`ADK_EXPERIMENTAL_TELEMETRY` is set (`telemetry/context.py:115-118`,
`telemetry/_instrumentation.py:586-589`). Set it, run the turn, then unset it so
the rest of Part 1 stays on the framework six.

**Step 1 — Turn it on.**

**Command:**

```bash
export ADK_EXPERIMENTAL_TELEMETRY=true
.venv/bin/python examples/01_console_metrics.py
grep -o '"name": "\(gen_ai\|adk\)[^"]*"' out/metrics.json | sort -u
```

The `grep` lists the metric names in `out/metrics.json`, the same file as
[1.1](1.1-your-first-datapoint.md). Open the file in your editor to read the
datapoints.

**Expected output:** the answer, then twelve metric names instead of six:

```console
(metrics written to out/metrics.json)

AGENT: The current weather in London is 15°C and drizzling.

"name": "adk.experimental.invoke_agent.cache_read.input_tokens"
"name": "adk.experimental.invoke_agent.input_tokens"
"name": "adk.experimental.invoke_agent.output_tokens"
"name": "adk.experimental.invoke_agent.reasoning.output_tokens"
"name": "adk.experimental.invoke_agent.tool.input_tokens"
"name": "adk.experimental.invoke_agent.total_tokens"
"name": "gen_ai.client.operation.duration"
"name": "gen_ai.client.token.usage"
"name": "gen_ai.execute_tool.duration"
"name": "gen_ai.invoke_agent.duration"
"name": "gen_ai.invoke_agent.inference_calls"
"name": "gen_ai.invoke_agent.tool_calls"
```

> [!IMPORTANT]
> **What it means.** These sum tokens over the whole invocation, not per model
> call. Where `gen_ai.client.token.usage` records once per call (twice a turn
> here), `adk.experimental.invoke_agent.total_tokens` records once per turn, so
> its `sum` is the turn's total and its `count` is the turns. It also breaks
> tokens out by source: cache reads, reasoning output, and tool input each get
> their own name.

> [!WARNING]
> These are ADK's own instruments, not the OpenTelemetry GenAI standard, so
> their names or gates can change between versions; do not alert on them.

**Step 2 — Turn it off.**

**Command:**

```bash
unset ADK_EXPERIMENTAL_TELEMETRY
.venv/bin/python examples/01_console_metrics.py
grep -o '"name": "\(gen_ai\|adk\)[^"]*"' out/metrics.json | sort -u
```

**Expected output:** the six framework names only.

```console
(metrics written to out/metrics.json)

AGENT: The current weather in London is 15°C with drizzle.

"name": "gen_ai.client.operation.duration"
"name": "gen_ai.client.token.usage"
"name": "gen_ai.execute_tool.duration"
"name": "gen_ai.invoke_agent.duration"
"name": "gen_ai.invoke_agent.inference_calls"
"name": "gen_ai.invoke_agent.tool_calls"
```

> [!IMPORTANT]
> **What it means.** All six experimental names vanish. The environment variable
> is the default switch (`1` or `true`). A per-request `RunConfig` setting can
> also turn it on (`telemetry/context.py:276-290`), so nothing downstream sees
> these metrics unless someone opts in.

[1.5](1.5-workflow-grain-metrics.md) adds a second agent to show how agent-level
metrics split by agent name.
