# 1.3 · Attributes and cardinality

*Part 1 · What a metric is*

> [!NOTE]
> **Why you are here.** Attributes split one metric into separate series. This
> page makes a tool fail, watches its metric split, and explains why an
> identifier like a session id must never be an attribute.

The `unknown-city` scenario asks about two cities in one process: London, which
`get_weather` knows, and Atlantis, which it does not.
[examples/02_two_attribute_sets.py](../../examples/02_two_attribute_sets.py) runs
both, then flushes.

**👉 Do this.**

**Command:**

```bash
.venv/bin/python examples/02_two_attribute_sets.py
```

**Expected output:** the two agent answers, then the tool metric, trimmed to its
attribute sets.

```console
AGENT (London): The current weather in London is 15°C with drizzle.
AGENT (Atlantis): I do not have weather data for Atlantis.

gen_ai.execute_tool.duration
  {gen_ai.tool.name=get_weather, gen_ai.tool.type=StatusAwareTool}                  count=1
  {gen_ai.tool.name=get_weather, gen_ai.tool.type=StatusAwareTool, error.type=no_data}  count=1
```

> [!IMPORTANT]
> **What it means.** One metric, two series. The Atlantis turn added
> `error.type=no_data`, so the failing calls are counted separately from the
> healthy ones. `gen_ai.invoke_agent.duration` gained no such split: the tool
> failed, but the agent answered the user, so the invocation succeeded. That gap,
> a failed tool inside a successful turn, is the whole reason [Part 3](../part-3/index.md)
> exists.

> [!WARNING]
> `error.type` is not free. See the deep dive.

## Deep dives

### Why does the failing tool need a hook?

A plain function that returns `{"status": "error"}` does not stamp `error.type`.
ADK reads a tool's response for an error only through the optional
`_detect_error_in_response` hook, which `FunctionTool` leaves returning `None`
(`flows/llm_flows/functions.py:88`; `telemetry/_instrumentation.py:525`). The
demo wraps its tools in a small subclass that overrides it:

```python
class StatusAwareTool(FunctionTool):
    def _detect_error_in_response(self, response):
        if isinstance(response, dict) and response.get("status") == "error":
            return "no_data"
        return None
```

Raising an exception from the tool would also stamp `error.type` (the exception
class name), but it crashes the invocation, so the turn fails instead of
answering. The hook is the path that fails the tool while keeping the turn
successful.

### Why can't I put a session id on a metric?

Attributes multiply series. Two tools times two outcomes is four series, which is
cheap. A session id is unbounded: a new value on every conversation, so a new
series on every conversation, forever. Backends bill and slow down on series
count, so ADK keeps metric attributes to a bounded set and never records a
session, user, or invocation id (`telemetry/_metrics.py:585-590`). When you need
to find one user's slow turn, you go to the rows in [Part 4](../part-4/index.md),
not the metrics.

[1.4](1.4-the-experimental-family.md) turns on a family of metrics that stays off
by default.
