# 1.5 · Workflow-grain metrics

*Part 1 · What a metric is*

> [!NOTE]
> **Why you are here.** Every other page uses one agent. This reference page adds
> a second one so you can see how metrics attribute themselves when a single turn
> runs more than one agent. Then the tutorial returns to the single agent.

The `workflow` scenario wraps two agents in a
[SequentialAgent](../../examples/05_workflow_metrics.py): a `planner` that
restates the city, then the `weather_agent` you already know. One user turn now
runs both.

**👉 Do this.**

**Command:**

```bash
.venv/bin/python examples/05_workflow_metrics.py
```

The script writes the metrics JSON to `out/metrics.json`. Open it in your editor
to read it; the dump is too long for the terminal. In VS Code:

```bash
code out/metrics.json
```

**Expected output:** `gen_ai.invoke_agent.duration` now carries three data
points. Trimmed to the agent name, count, and sum:

```console
{
    "name": "gen_ai.invoke_agent.duration",
    "unit": "s",
    "data": { "data_points": [
        { "attributes": { "gen_ai.agent.name": "planner" },          "count": 1, "sum": 3.20 },
        { "attributes": { "gen_ai.agent.name": "weather_agent" },    "count": 1, "sum": 4.74 },
        { "attributes": { "gen_ai.agent.name": "weather_workflow" }, "count": 1, "sum": 7.94 }
    ] }
}
```

> [!IMPORTANT]
> **What it means.** The `gen_ai.agent.name` attribute splits agent duration per
> agent. The `weather_workflow` series is the container: its 7.94 s spans both
> children plus the sequencing between them, so it is roughly the sum of `planner`
> and `weather_agent`, not a fourth independent measurement. Reading the outer
> series as extra work would double-count.

> [!IMPORTANT]
> **What it means, on the seventh metric.** There is still no
> `gen_ai.invoke_workflow.duration`. A `SequentialAgent` is measured as an outer
> agent, not a workflow; only ADK's newer `Workflow` primitive records the
> dedicated workflow metric (`workflow/_node_runner.py`,
> `telemetry/node_tracing.py:254`). For a simple sequence, the agent-grain series
> above are what you get.

> [!WARNING]
> `SequentialAgent` is deprecated in google-adk 2.8.0 in favor of `Workflow`; you
> will see a `DeprecationWarning` at construction. This tutorial keeps it for the
> simplest possible two-agent topology. When you adopt `Workflow`, expect
> `gen_ai.invoke_workflow.duration` to appear with a `gen_ai.workflow.name`
> attribute.

That is the only multi-agent page. Everything from
[Part 2](../part-2/index.md) on uses the single `weather_agent` and its six
metrics, now shipped off the laptop and into Cloud Monitoring.
