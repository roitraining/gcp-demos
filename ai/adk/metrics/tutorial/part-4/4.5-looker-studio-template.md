# 4.5 · The Looker Studio template

*Part 4 · Consume: rows in BigQuery*

> [!NOTE]
> **Why you are here.** Can a teammate without SQL see the same answers? A
> ready-made Looker Studio report charts the `agent_events` table you already
> have, so they read charts instead of queries.

The template is a 37-chart report that binds to one BigQuery table. It is a
browser workflow, so this page has no captured console output; you follow the
steps and confirm the charts fill with your data. It reads the rows the
`baseline`, `growing-context`, `multi-city` and `unknown-city` runs of 4.1 to 4.4
left in the table.

**Step 1 — Build your copy with the configurator.** The template's
[README](https://github.com/GoogleCloudPlatform/BigQuery-Agent-Analytics-SDK/blob/main/dashboard/looker_studio/README.md)
uses a configurator that builds a Looker Studio Linking API URL for your table.

- Open the [dashboard configurator](https://googlecloudplatform.github.io/BigQuery-Agent-Analytics-SDK/).
- Enter your table id as `<project>.agent_analytics.agent_events`.
- Open the URL it generates and authorize BigQuery access.
- Click **Edit and share** to save the report, and keep it private.
- Open **Resource → Manage added data sources → Edit**.
- Set **Data credentials** to **Viewer**.

**Step 2 — Read the pages.** The report has eight pages that share one date
control, set by default to the last 90 days. Seven match the tiles of the Looker
agent-analytics block, including **Token Consumption** and **Latency**, the
questions [4.2](4.2-tokens-latency-cache-per-call.md) and
[4.3](4.3-cost-per-session-and-user.md) answered with queries. The eighth, the
**Trace Inspector**, shows one trace's events, as [4.4](4.4-the-sdk.md)'s
`render()` did.

> [!IMPORTANT]
> **What it means.** The charts read the same rows your queries did, so a session
> that topped the SQL ranking tops the chart too. The template is a presentation
> layer over `agent_events`, not a separate store; it adds no data and no cost
> beyond the query volume Looker Studio runs.

> [!TIP]
> With **Viewer** credentials, every viewer needs their own read access to the
> dataset, and sees whatever the charts show, including prompt text on the
> **Trace Inspector** page.

**Step 3 — Delete your copy.** Delete the report when you finish this page; it
stops working once [4.6](4.6-metrics-or-rows.md) deletes the dataset.

[4.6](4.6-metrics-or-rows.md) closes the part by following a row into Cloud
Trace and tearing down the dataset.
