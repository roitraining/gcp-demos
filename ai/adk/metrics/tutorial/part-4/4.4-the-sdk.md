# 4.4 · The SDK

*Part 4 · Consume — rows in BigQuery*

> [!NOTE]
> **Why you are here.** SQL reads one column at a time. The
> `bigquery-agent-analytics` SDK reads the whole invocation at once, replays it in
> order, and scores it, so you debug one failing turn without writing a join.

Run the `unknown-city` scenario so there is a failing invocation to inspect: half
the turns ask for Atlantis, which `get_weather` cannot answer.

**Command:**

```bash
load/turns.sh unknown-city 10
```

**Expected output:**

```console
NEEDS-RUN: turns.sh printing ten unknown-city turns, roughly half asking for Atlantis
```

**Step 1 — Install the SDK.**

The SDK reads the same `agent_events` table the plugin wrote; it needs no new
resource.

**Command:**

```bash
.venv/bin/pip install bigquery-agent-analytics
```

**Expected output:**

```console
NEEDS-RUN: pip install of bigquery-agent-analytics 0.5.2 and its dependencies
```

**Step 2 — Render one invocation.**

Pick an Atlantis invocation id from [4.3](4.3-cost-per-session-and-user.md)'s
prompt query, then replay it. `render()` prints the invocation's events in order:
the user message, each model call, each tool call, and the final response.

**Command:**

```bash
export BQ_TRACE_ID=<invocation id from the query above>
.venv/bin/python -c "from bigquery_agent_analytics import Client; import os; Client(os.environ['GOOGLE_CLOUD_PROJECT'], os.environ['BQ_ANALYTICS_DATASET_ID']).get_trace(os.environ['BQ_TRACE_ID']).render()"
```

**Expected output:**

```console
NEEDS-RUN: render() output replaying one unknown-city invocation: user asks for Atlantis, model calls get_weather, tool returns an error status, model answers that it has no data
```

> [!IMPORTANT]
> **What it means.** One call reconstructs the turn from its rows in event order.
> This is the row-store's answer to "what actually happened", the detail a
> histogram folded away. The failing tool call and the model's recovery are both
> visible in the replay.

**Step 3 — Score the run with the system evaluator.**

The SDK ships a system evaluator that summarizes the whole table: latency, turn
count, tool error rate, token efficiency, TTFT, and cost. It is the aggregate view
over the rows, computed for you.

**Command:**

```bash
.venv/bin/bq-agent-sdk evaluate \
  --project "${GOOGLE_CLOUD_PROJECT}" \
  --dataset "${BQ_ANALYTICS_DATASET_ID}"
```

**Expected output:**

```console
NEEDS-RUN: bq-agent-sdk evaluate summary: latency percentiles, turn count, tool error rate near 0.5 for unknown-city, token efficiency, TTFT, cost estimate
```

> [!IMPORTANT]
> **What it means.** The tool error rate reads near 0.5 because half the turns
> asked for Atlantis, matching the tool error ratio the metric side computed in
> Part 3. Two stores, one number again: the evaluator derives it from rows, the
> PromQL query derived it from histogram series.

[4.5](4.5-looker-studio-template.md) points a ready-made dashboard at the same
table so a reader without SQL or the SDK can see these answers.

## Deep dives

### What else does the CLI do?

`bq-agent-sdk` wraps the same client for the shell. Beyond `evaluate`, it lists
recent traces and renders one by id, so you can triage from a terminal without
opening Python. The subcommands read only; they never write to the table the
plugin owns.
