# 4.4 · The SDK

*Part 4 · Consume: rows in BigQuery*

> [!NOTE]
> **Why you are here.** SQL reads one column at a time. The
> `bigquery-agent-analytics` SDK reads the whole invocation at once, replays it in
> order, and scores it, so you debug one failing turn without writing a join.

Run the `unknown-city` scenario so there is a failing invocation to inspect: half
the turns ask for Atlantis, which `get_weather` cannot answer.

**Command:**

```bash
load/turns.sh unknown-city 10
```

**Expected output:**

```console

unknown-city    turn   2  http=200  3.76s
unknown-city    turn   3  http=200  4.77s
unknown-city    turn   4  http=200  4.81s
unknown-city    turn   5  http=200  3.64s
unknown-city    turn   6  http=200  3.95s
unknown-city    turn   7  http=200  4.43s
unknown-city    turn   8  http=200  3.69s

unknown-city    turn  10  http=200  4.00s

```

**Step 1 — Confirm the SDK is installed.**

The SDK reads the same `agent_events` table the plugin wrote; it needs no new
resource. Setup's `requirements.txt` already installed it.

**Command:**

```bash
.venv/bin/pip show bigquery-agent-analytics
```

**Expected output** (trimmed):

```console
Name: bigquery-agent-analytics
Version: 0.5.2
Summary: SDK for analyzing and evaluating agent traces stored in BigQuery.
```

**Step 2 — Render one invocation.**

`get_trace()` looks rows up by `trace_id`, not `invocation_id`
(`bigquery_agent_analytics/client.py:913-948`); given an invocation id it raises
`No events found`. Find an Atlantis turn's `trace_id` with
[4.3](4.3-cost-per-session-and-user.md)'s prompt query, filtered to Atlantis.

**Command:**

```bash
bq query \
  --use_legacy_sql=false \
  "SELECT invocation_id, trace_id, JSON_VALUE(content, '\$.text_summary') AS prompt FROM \`${GOOGLE_CLOUD_PROJECT}.${BQ_ANALYTICS_DATASET_ID}.agent_events\` WHERE event_type = 'USER_MESSAGE_RECEIVED' AND JSON_VALUE(content, '\$.text_summary') LIKE '%Atlantis%' ORDER BY timestamp DESC LIMIT 1"
```

**Expected output:**

```console
+----------------------------------------+----------------------------------+---------------------------------+
|             invocation_id              |             trace_id             |             prompt              |
+----------------------------------------+----------------------------------+---------------------------------+
| e-8c460a77-abf8-4c31-8257-5a861232243b | 6228f79f57409eedd3189d9fc4a2f4b1 | What's the weather in Atlantis? |
+----------------------------------------+----------------------------------+---------------------------------+
```

Set `BQ_TRACE_ID` to the `trace_id` from your own output, then replay the turn.
`render()` prints its events as a tree: the user message, each model call, each
tool call, and the final response.

**Command:**

```bash
export BQ_TRACE_ID=6228f79f57409eedd3189d9fc4a2f4b1
.venv/bin/python -c "from bigquery_agent_analytics import Client; import os; Client(os.environ['GOOGLE_CLOUD_PROJECT'], os.environ['BQ_ANALYTICS_DATASET_ID']).get_trace(os.environ['BQ_TRACE_ID']).render()"
```

**Expected output:**

```console
Trace: 6228f79f57409eedd3189d9fc4a2f4b1 | Session: 64c3cd79-c20a-4c2a-8457-3739cfec2a89 | 3352ms
================================================================================================
└─ [✓] USER_MESSAGE_RECEIVED [weather_agent] - What's the weather in Atlantis?
└─ [✓] INVOCATION_STARTING [weather_agent]

└─ [✓] INVOCATION_COMPLETED [weather_agent] (3352ms)
   ├─ [✓] AGENT_STARTING [weather_agent] - You are a concise weather assistant. For a current-weather question, call get_weather. For a multi-day forecast, call...
   └─ [✓] AGENT_COMPLETED [weather_agent] (3350ms)
      ├─ [✓] LLM_REQUEST [weather_agent] (gemini-3.7-flash) - What's the weather in Atlantis?
      ├─ [✓] LLM_RESPONSE [weather_agent] (1475ms) - call: get_weather
      ├─ [✓] TOOL_STARTING [weather_agent] (get_weather)
      ├─ [✓] TOOL_COMPLETED [weather_agent] (get_weather) (1ms)

      └─ [✓] LLM_RESPONSE [weather_agent] (1861ms) - I do not have weather data for Atlantis.
```

> [!IMPORTANT]
> **What it means.** One call reconstructs the turn from its rows in event order.
> This is the row-store's answer to "what actually happened", the detail a
> histogram folded away. Note the tool row: `TOOL_COMPLETED` with a `✓`.
> `get_weather` returned an error status instead of raising, so the plugin logged
> a completed call; the failure shows only in the model's answer.

**Step 3 — Score the run with the system evaluator.**

The SDK ships system evaluators that score every session in the table, one per
run: `latency` (the default), `error_rate`, `turn_count`, `token_efficiency`, and
`ttft`. Run the tool error rate, the number Part 3 read from histograms.

**Command:**

```bash
.venv/bin/bq-agent-sdk evaluate \
  --project-id "${GOOGLE_CLOUD_PROJECT}" \
  --dataset-id "${BQ_ANALYTICS_DATASET_ID}" \
  --evaluator error_rate \
  --format text
```

**Expected output:**

```console
Evaluation Report: error_rate_evaluator
  Dataset: jwd-gcp-demos.agent_analytics.agent_events WHERE TRUE
  Sessions: 41
  Passed: 41 (100%)
  Failed: 0
  Aggregate Scores:
    error_rate: 1.000
```

> [!IMPORTANT]
> **What it means.** Every session passed: the evaluator saw no tool errors, even
> though half of this run asked for Atlantis. It counts `TOOL_ERROR` rows
> (`bigquery_agent_analytics/system_evaluator.py:643`), and the plugin writes one
> only when a tool raises. Part 3's metric counted the same calls as errors
> because `StatusAwareTool` stamps `error.type` on a failure status
> ([1.3](../part-1/1.3-attributes-and-cardinality.md)). Two stores, two
> definitions of failure: settle which one you mean before comparing numbers.

[4.5](4.5-looker-studio-template.md) points a ready-made dashboard at the same
table so a reader without SQL or the SDK can see these answers.

## Deep dives

### What else does the CLI do?

`bq-agent-sdk` wraps the same client for the shell. Beyond `evaluate`,
`list-traces` lists recent traces and `get-trace` renders one by `trace_id`, so you
can triage from a terminal without opening Python. Both read only. Other
subcommands, such as `views` and `categorical-views`, create objects in the
dataset, so check `bq-agent-sdk --help` before running one against a shared table.
