# 4.2 · A custom server that owns streams 1–3

*Part 4 · Structured logging*

> [!NOTE]
> **Why you are here.** You have a hand-written FastAPI service, not `adk web`
> or `adk api_server`, and you want to configure your code, the framework, and
> uvicorn in one place. `get_fast_api_app` has no `log_level` parameter either,
> so owning the logging config is the norm for any custom server.

[examples/06_custom_server.py](../../examples/06_custom_server.py) is a complete,
minimal server. One `dictConfig` at startup sets up streams 1 to 3, and its
formatter writes three fields Cloud Logging understands: `severity` from the
record's level, the request's trace id in `logging.googleapis.com/trace`, and
the code location in `logging.googleapis.com/sourceLocation`.
See [What does the server look like?](#what-does-the-server-look-like) and
[Which fields does the formatter write?](#which-fields-does-the-formatter-write)

**👉 Do this.** Start the server, then send a turn with the trace header Cloud
Run would set.

**Command:**

```bash
source env.sh
.venv/bin/python examples/06_custom_server.py
```

In another terminal:

**Command:**

```bash
curl -s \
  -X POST localhost:8080/chat \
  -H 'content-type: application/json' \
  -H 'X-Cloud-Trace-Context: 105445aa7843bc8bf206b12000100000/1;o=1' \
  -d '{"message":"What'\''s the weather in Tokyo?"}'
```

**Expected output** (the server terminal, trimmed to one model call and the
access line): your app log, your plugin telemetry, and ADK's own framework log
all carry the same trace value.

> [!IMPORTANT]
> **What it means.** Your code, the framework, and uvicorn share one config
> (streams 1–3), and the 4.1 events flow out of a real HTTP server. Stream 4 is
> Part 5. The `tool get_weather called` and `Sending out request` lines are logs
> you did not write, and they still carry the trace, because a `ContextVar`
> threads it through everything that runs during the request. The access line
> has no trace: uvicorn writes it after the handler clears the trace id. See
> [How does the trace reach framework logs?](#how-does-the-trace-reach-framework-logs)

4.3 ships this server unchanged to Cloud Run.

## Deep dives

### What does the server look like?

The server builds an `App` with your plugin, hands it to a `Runner`, and closes
the runner on shutdown:

```python
adk_app = App(name="custom_server", root_agent=root_agent,
              plugins=[StructuredTelemetryPlugin()])   # the 4.1 plugin

@asynccontextmanager
async def lifespan(app):
    app.state.runner = Runner(app=adk_app, session_service=InMemorySessionService())
    yield
    await app.state.runner.close()      # releases plugin/toolset resources
```

Passing `app=` to the `Runner` is the recommended form; `plugins=` on the
`Runner` still works but is deprecated.

The `dictConfig` at startup covers your telemetry logger, the `google_adk`
level, and the root handler. With `log_config=None`, uvicorn's access lines
reach that root handler as JSON. The same config attaches a filter that
truncates long DEBUG lines.

### Which fields does the formatter write?

Cloud Run ingests stdout into Cloud Logging, so the only job is to make each
line a good JSON object with special fields. Two matter here; the third,
`logging.googleapis.com/sourceLocation`, records the file and line:

- **`severity` lives in the JSON, not in the stream.** 1.4 and 1.5 showed Cloud
  Run filing plain `INFO -` lines as Default. `CloudRunJsonFormatter` writes the
  record's level as a field instead.
- **`logging.googleapis.com/trace` groups a request.** Cloud Run sets an
  `X-Cloud-Trace-Context` header on each request. Put it into that field as
  `projects/PROJECT_ID/traces/TRACE_ID` and Logs Explorer groups every line
  written while the request runs: your code, the plugin, and `google_adk`.

```mermaid
flowchart LR
  subgraph after["after · JSON to stdout"]
    B1["{severity: INFO, ...}"] -->|"Cloud Logging<br/>parses"| B2["severity = INFO ✓"]
  end
  subgraph before["before · plain text to stderr"]
    A1["INFO - google_adk..."] -->|"Cloud Run<br/>guesses"| A2["severity = Default ✗"]
  end
```

*Plain text vs. JSON: the severity you get depends on whether you set it yourself or let Cloud Run guess.*

### How does the trace reach framework logs?

A `contextvars.ContextVar` carries the trace. The `/chat` handler parses it
once at the start of each request, and the formatter reads it for every record
emitted while that request is handled, including the `google_adk` records you
never touch:

```python
current_trace: ContextVar[str | None] = ContextVar("current_trace", default=None)

class CloudRunJsonFormatter(logging.Formatter):
    def format(self, record):
        entry = {"severity": record.levelname, "message": record.getMessage()}
        trace_id = current_trace.get()
        if trace_id and PROJECT_ID:
            entry["logging.googleapis.com/trace"] = f"projects/{PROJECT_ID}/traces/{trace_id}"
        # ... plus any extra= fields from your plugin ...
        return json.dumps(entry, default=str)
```

