# 6.4 · What the platform changes

*Part 6 · Agent Runtime*

> [!NOTE]
> **Why you are here.** This page collects what 6.2 and 6.3 showed about a
> native Agent Runtime deploy in one table, as reference.

What the two read-backs showed, and no further:

| On a native Agent Runtime deploy | What we observed |
|---|---|
| **The enablement switch** | One env var, `GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY`, on the deployment. Both methods set the variable to `true` and add `--otel_to_cloud` to the server's start command. |
| **Who sets the content knobs** | The flag route also sets `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false`; the `.env` route sets nothing, so you set both knobs. Proven by the two env lists. |
| **The logs you get** | The framework INFO lines land on `aiplatform.googleapis.com/reasoning_engine_stderr` (stdout carries only access lines). Same ADK-native logging as Part 1, captured by the platform. |
| **The `gen_ai.*` OTel events** | Did **not** surface in Cloud Logging or Cloud Trace in our testing, unlike Cloud Run (5.4). Open question; see the [Verification status](../how-to-choose.md). |

Check your own project's Trace Explorer and Logs Explorer; this tutorial did not
establish where Agent Runtime sends telemetry. For other export targets, see
[5.7](../part-5/5.7-other-backends.md).
