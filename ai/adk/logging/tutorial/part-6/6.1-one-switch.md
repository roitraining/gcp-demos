# 6.1 · One switch, two ways to set it

*Part 6 · Agent Runtime*

> [!NOTE]
> **Why you are here.** Before deploying, learn the one variable that turns
> telemetry on and the two ways this tutorial sets it, which are not equivalent.

Telemetry on Agent Runtime is governed by one environment variable on the
deployment: `GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY`. On a deploy with
`adk deploy agent_engine`, the CLI reads the variable when you deploy and adds
`--otel_to_cloud` to the container's `adk api_server`. A BYOC container built on
`AdkApp` reads it at startup: `true` or `1` turns telemetry on, `false` or `0`
turns it off, and anything else (including the literal `unspecified` the SDK
injects when you set nothing) leaves it to the platform.

From this folder there are two ways to write it, and they are not equivalent:

| Route | What it writes | Source |
|---|---|---|
| The flag: `adk deploy agent_engine --otel_to_cloud` | `GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true` and `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false` | `google/adk/cli/cli_deploy.py:1273-1282` (google-adk 2.8.0) |
| A `.env` line: `GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true`, no flag | that one variable only; the CLI sets no content settings | `google/adk/cli/cli_deploy.py:1283-1292` (google-adk 2.8.0); the value must be `true` or `1` |

Both routes add `--otel_to_cloud` to the server's start command
(`cli_deploy.py:1392`). The flag turns off message content on spans only.
Content in the `gen_ai.*` log events is controlled by
`OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT`, which stays at its default
unless you set it. See [5.6](../part-5/5.6-content-knobs.md). On the `.env`
route you add both content settings yourself.

Set the variable explicitly. If you set neither, the SDK sends `unspecified`
and the platform decides. See
[What other ways set the variable?](#what-other-ways-set-the-variable)

6.2 deploys with the flag.

## Deep dives

### What other ways set the variable?

Two other routes exist but are not run here:
`agent_engines.update(config={"env_vars": …})` via the `vertexai` SDK, and the
Cloud Console toggle.

The BYOC container from 1.7 also reads the variable, if its deploy passes it.
`agent_runtime_byoc/deploy_byoc.py` passes `LOG_LEVEL`,
`GOOGLE_GENAI_USE_VERTEXAI`, and `MODEL_LOCATION`, not this variable, so the
platform decides. In the 2026-10-02 run of 1.7 the container logged
`telemetry enabled but proceeding without GenAI instrumentation`.
