# 6.1 · One switch, two ways to set it

*Part 6 · Agent Runtime*

Telemetry on Agent Runtime is governed by one environment variable on the
deployment: **`GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY`**. The `AdkApp`
wrapper reads it at startup. `true` turns telemetry on, `false` off, and
anything else (including the literal `unspecified` the SDK injects when you set
nothing) leaves it to the platform.

From this folder there are two ways to write it, and **they are not
equivalent**:

| Route | What it writes | Source |
|---|---|---|
| **The flag**: `adk deploy agent_engine --otel_to_cloud` | `GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true` **and** `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false` (the span knob, set safe for you) | `cli/cli_deploy.py:1273-1282` |
| **A `.env` line**: `GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true`, no flag | that one variable only; **the CLI sets no content knobs** | `cli/cli_deploy.py:1283-1291` |

On the `.env` route **you** add the content knobs, or prompt text ships in the
telemetry. 6.2 and 6.3 run each route and read the deployment's env list back
to prove what each one wrote.

Set the variable explicitly. If you set neither, the SDK sends `unspecified`
and the platform decides. Two other routes exist but are not run here:
`agent_engines.update(config={"env_vars": …})` via the `vertexai` SDK, and the
Cloud Console toggle.

> [!NOTE]
> **BYOC.** The same env var governs a custom container's `AdkApp`, **if your
> deploy passes it.** The BYOC script here passes only project, location, and
> log level, so telemetry is off on that path until you add the variable. Not
> run here.
