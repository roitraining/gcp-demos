# 6.3 · Deploy B: the `.env` route

*Part 6 · Agent Runtime*

Same deploy, but the telemetry vars come from `.env` instead of the flag.
`6.2b.env` carries `GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true` **and both
content knobs**, and the deploy drops `--otel_to_cloud`.

**Command:**

```bash
source env.sh
cp deploy/env/6.2b.env demo_agent/.env

DEPLOY_OUT=$(.venv/bin/adk deploy agent_engine \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --display_name="adk-logging-demo" \
  ./demo_agent 2>&1 | tee /dev/stderr)

export ENGINE_ID_ENV=$(printf '%s\n' "$DEPLOY_OUT" \
  | grep -oE 'reasoningEngines/[0-9]+' | tail -n1 | cut -d/ -f2)
```

**Read this deployment's env list**, passing `$ENGINE_ID_ENV`.

**Command:**

```bash
.venv/bin/python - "$GOOGLE_CLOUD_PROJECT" "$REGION" "$ENGINE_ID_ENV" <<'PY'
import sys, vertexai
project, region, engine_id = sys.argv[1], sys.argv[2], sys.argv[3]
c = vertexai.Client(project=project, location=region)
e = c.agent_engines.get(
    name=f"projects/{project}/locations/{region}/reasoningEngines/{engine_id}"
)
for ev in e.api_resource.spec.deployment_spec.env:
    print(f"{ev.name}={ev.value}")
PY
```

**Expected output** — exactly the lines `.env` carried, and nothing the CLI
added:

```console
GOOGLE_GENAI_USE_VERTEXAI=TRUE
GOOGLE_CLOUD_LOCATION=global
LOG_LEVEL=info
GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true
ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false
OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=NO_CONTENT
```

> [!IMPORTANT]
> **What it means.** In 6.2 the CLI added `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false`
> on its own. Here all three telemetry lines came from `.env`, including the
> event knob the flag route never set. On the `.env` route the CLI adds no
> content knobs, so every knob is yours. Had `6.2b.env` omitted the span knob,
> prompt text would ride on the spans.

**Send a query and read the logs back.** Agent Runtime logs lag ingestion, so the
`sleep 15` gives them time to land before the read.

**Command:**

```bash
.venv/bin/python - "$GOOGLE_CLOUD_PROJECT" "$REGION" "$ENGINE_ID_ENV" <<'PY'
import sys, vertexai
project, region, engine_id = sys.argv[1], sys.argv[2], sys.argv[3]
c = vertexai.Client(project=project, location=region)
a = c.agent_engines.get(
    name=f"projects/{project}/locations/{region}/reasoningEngines/{engine_id}"
)
for ev in a.stream_query(user_id="u1", message="What's the weather in London?"):
    pass
print("query sent")
PY

sleep 15

gcloud logging read \
  'resource.type="aiplatform.googleapis.com/ReasoningEngine"
   resource.labels.reasoning_engine_id="'"$ENGINE_ID_ENV"'"' \
  --project="$PROJECT_ID" \
  --limit=10 \
  --format='value(logName.basename(), textPayload)'
```

The logs are the same `reasoning_engine_stderr` INFO lines as 6.2, and the same
absence of `gen_ai.*` events. The `.env` route changes what the deployment
*carries*, not what surfaces in Logging.

Restore the base `.env` when you are done.

**Command:**

```bash
cp deploy/env/default.env demo_agent/.env
```
