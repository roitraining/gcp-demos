# 6.3 · Deploy B: the `.env` route

*Part 6 · Agent Runtime*

> [!NOTE]
> **Why you are here.** 6.2 let the flag write the telemetry vars. This page
> puts them in `.env` instead and shows that you then own the content settings.

Same deploy, but the telemetry vars come from `.env` instead of the flag.
`6.2b.env` carries `GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true` and both
content settings, including `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT`,
which controls prompt and reply text in log events (see
[5.6](../part-5/5.6-content-knobs.md)). The command omits `--otel_to_cloud`; the
CLI reads the `.env` value and adds the flag to the server command itself.

**Step 1 — Stage the env file and deploy.** The deploy takes several minutes.

**Command:**

```bash
source env.sh
cp deploy/env/6.2b.env demo_agent/.env

DEPLOY_OUT=$(.venv/bin/adk deploy agent_engine \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --display_name="adk-logging-demo" \
  ./demo_agent 2>&1 | tee /dev/stderr)

export ENGINE_ID_ENV=$(printf '%s\n' "$DEPLOY_OUT" \
  | grep -oE 'reasoningEngines/[0-9]+' | tail -n1 | cut -d/ -f2)
```

**Expected output** (one line of the deploy output):

```console
`--otel_to_cloud` is set to True by GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY in .../ai/adk/logging/demo_agent/.env
```

**Step 2 — Read this deployment's env list.**

**Command:**

```bash
.venv/bin/python - "$PROJECT_ID" "$REGION" "$ENGINE_ID_ENV" <<'PY'
import sys, vertexai
project, region, engine_id = sys.argv[1], sys.argv[2], sys.argv[3]
c = vertexai.Client(project=project, location=region)
e = c.agent_engines.get(
    name=f"projects/{project}/locations/{region}/reasoningEngines/{engine_id}"
)
for ev in e.api_resource.spec.deployment_spec.env:
    print(f"{ev.name}={ev.value}")
PY
```

**Expected output** (exactly the lines `.env` carried, and nothing the CLI
added):

```console
GOOGLE_GENAI_USE_VERTEXAI=TRUE
GOOGLE_CLOUD_LOCATION=global
LOG_LEVEL=info
GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true
ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false
OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=NO_CONTENT
```

> [!IMPORTANT]
> **What it means.** In 6.2 the CLI added `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false`
> on its own. Here all three telemetry lines came from `.env`, including the
> event setting the flag route never set. On the `.env` route the CLI adds no
> content settings, so every setting is yours. Had `6.2b.env` omitted the span
> setting, the span attributes would carry prompt text (default `true`,
> `google/adk/telemetry/context.py:107-113`), though no spans appeared on Agent
> Runtime in these runs.

**Step 3 — Send a query and read the logs back.** Run 6.2's Step 3 command with
`$ENGINE_ID_ENV` in place of `$ENGINE_ID`. The output is the same
`reasoning_engine_stderr` INFO lines as 6.2, and the same absence of `gen_ai.*`
events. The `.env` route changes what the deployment carries, not what surfaces
in Logging.

**Step 4 — Remove the staged `.env`.**

**Command:**

```bash
rm demo_agent/.env
```

**Step 5 — Tear down.**

**Command:**

```bash
.venv/bin/python - <<PY
import vertexai
vertexai.Client(project="$PROJECT_ID", location="$REGION").agent_engines.delete(
    name="projects/$PROJECT_ID/locations/$REGION/reasoningEngines/$ENGINE_ID_ENV",
    force=True)
PY
```

6.4 collects what the two deploys showed.
