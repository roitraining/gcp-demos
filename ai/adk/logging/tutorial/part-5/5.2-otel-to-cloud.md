# 5.2 · One flag: `adk web --otel_to_cloud`, read the events back from Cloud Logging

*Part 5 · OpenTelemetry*

> [!NOTE]
> **Why you are here.** 5.1 left the spans in the server's memory. This page
> adds one flag and no code, reads one turn back from Cloud Logging as `gen_ai.*`
> events, and shows the settings that decide whether prompt text ships with them.

**Step 1 — Prepare the project, once.** These cover 5.2 through 5.4. Run them
on the machine that runs `adk web`. The flag authenticates with Application
Default Credentials (ADC), not `GOOGLE_API_KEY`, and takes the project from
`GOOGLE_CLOUD_PROJECT` in the shell. The identity ADC resolves to needs
`roles/telemetry.writer`, which covers traces, metrics, and logs. See
[Which roles and packages does the flag need?](../how-to-choose.md#which-roles-and-packages-does-the-flag-need)

**Command:**

```bash
gcloud auth application-default login
source env.sh
gcloud services enable telemetry.googleapis.com --project="$PROJECT_ID"
```

`requirements.txt` already installs the packages.

**Step 2 — Start the dev UI with the flag (terminal 1).** Stop the 5.1 server if
it is still running. The `export` must be in the shell before `adk web` starts;
it cannot go in `demo_agent/.env`. See
[Why can `.env` not set these?](../how-to-choose.md#why-can-env-not-set-these)

**Command:**

```bash
source env.sh
export OTEL_RESOURCE_ATTRIBUTES="service.instance.id=laptop-1,cloud.region=us-central1"
adk web --otel_to_cloud ./
```

`OTEL_RESOURCE_ATTRIBUTES` is a laptop-only workaround. Without it every metrics
export fails, and the error prints to terminal 1 every five seconds. Spans and
log events do not need it. See
[Why do metrics need `OTEL_RESOURCE_ATTRIBUTES`?](../how-to-choose.md#why-do-metrics-need-otel_resource_attributes)

Startup looks exactly like 5.1. A WARNING mentioning `GoogleGenAiSdkInstrumentor`
means ADK was installed without the `[otel-gcp]` extra. See
[What does the otel-gcp extra add?](#what-does-the-otel-gcp-extra-add)

Open `http://localhost:8000`, pick `demo_agent`, and ask the London question:

```
What's the weather in London?
```

The reply ends in something like `The weather in London is currently 15°C and
drizzling.` Terminal 1 shows the usual INFO lines and nothing about the export.
Leave the server running.

**Step 3 — Read the turn back.**

- Open **Logs Explorer** (`console.cloud.google.com/logs`).
- Turn on **Show query** (top right).
- Enter the query below in the **Query editor**, not the "Search all fields"
  box, which ignores operators like `=~`.

**Query:**

```
logName=~"gen_ai\."
```

You get eight entries for the one turn, spread across the turn's two `call_llm`
spans. This step runs the default event format: every message the model saw or
produced is its own log, and each span re-logs the full input it was given. So
the counts are two `gen_ai.system.message` (the system prompt, re-sent on each
call), four `gen_ai.user.message` (the question on the first call; the question,
the `get_weather` call, and the tool's response replayed on the second), and two
`gen_ai.choice`, one reply per call. Expand a `gen_ai.choice` entry.

**Expected output** (content elided, the event's fields in `jsonPayload`):

```console
{
  "jsonPayload": {
    "index": 0,
    "finish_reason": "STOP",
    "content": "<elided>"
  },
  "resource": {
    "type": "generic_node",
    "labels": { "location": "us-central1", "project_id": "jwd-gcp-demos", "namespace": "", "node_id": "" }
  },
  "labels": {
    "gen_ai.system": "vertex_ai",
    "event.name": "gen_ai.choice"
  },
  "logName": "projects/jwd-gcp-demos/logs/gen_ai.choice",
  "trace": "projects/jwd-gcp-demos/traces/c5fdba983e103412f76dbdf0175a5eb7",
  "spanId": "55f834ee252474c1"
}
```

> [!IMPORTANT]
> **What you are looking at.**
>
> | Field | Value here | What it is |
> |---|---|---|
> | `jsonPayload.content` | `<elided>` | `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` defaults to `NO_CONTENT`, so the entry records that a reply happened and nothing it said. Step 4 turns this on. `<elided>` applies to the log events only, not the spans |
> | `labels.event.name` | `gen_ai.choice` | which of the split events this is |
> | `trace` / `spanId` | `…c5fdba98…` / `55f834ee…` | stamped on every log record from the current span. OTel does this join with its own trace ids, which are not Part 4's. All eight entries share the `trace`; the `spanId` is one of the two `call_llm` spans |
> | `resource.type` | `generic_node` | derived from the `OTEL_RESOURCE_ATTRIBUTES` in Step 2 |

**Step 4 — Turn event content on.** Stop the server with Ctrl-C, export the
setting in the same shell (the Step 2 export is still set), and restart.

**Command:**

```bash
export OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true
adk web --otel_to_cloud ./
```

Ask the London question in a new session, run the query again, and expand the
newest entries. Same eight events, and `jsonPayload.content` now holds the
messages.

**Expected output** (`gen_ai.system.message`, the prompt verbatim):

```console
{
  "jsonPayload": {
    "content": "You are a concise weather assistant. When the user asks about weather, call the get_weather tool and report its result in one sentence. If the tool returns an error, say you do not have data for that city.\n\nYou are an agent. Your internal name is \"weather_agent\". The description about you is \"Answers questions about the weather in a few known cities.\"."
  },
  "labels": { "gen_ai.system": "vertex_ai", "event.name": "gen_ai.system.message" },
  "logName": "projects/jwd-gcp-demos/logs/gen_ai.system.message",
  "trace": "projects/jwd-gcp-demos/traces/9d24673b9690da24f0e5c44ad263e2fe",
  "spanId": "feed5573604bf3a9"
}
```

**Expected output** (the final `gen_ai.choice`, the model's reply):

```console
{
  "jsonPayload": {
    "content": {
      "role": "model",
      "parts": [{ "text": "The weather in London is currently 15°C and drizzling." }]
    },
    "finish_reason": "STOP",
    "index": 0
  },
  "labels": { "gen_ai.system": "vertex_ai", "event.name": "gen_ai.choice" },
  "logName": "projects/jwd-gcp-demos/logs/gen_ai.choice",
  "trace": "projects/jwd-gcp-demos/traces/9d24673b9690da24f0e5c44ad263e2fe",
  "spanId": "89d9503ddd1fe465"
}
```
> [!IMPORTANT]
> **What it means.** Every message the model saw and produced is now in Cloud
> Logging, under your project's retention and access rules: the system prompt,
> the question, the `get_weather` call and response, and the reply. Keep content
> off in production unless you have a reviewed reason to log it (5.6).

**Step 5 — Check the spans.**

- Open **Trace Explorer** (`console.cloud.google.com/traces`).
- Find this turn.
- Click a `call_llm` span.
- Look for `gcp.vertex.agent.llm_request` and `gcp.vertex.agent.llm_response` in
  its attributes.

The spans hold the prompt and reply, and did in Step 2 too:
`ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS` defaults to on and does not depend on the
event setting. Step 6 turns it off.

**Step 6 — Turn content off on the spans only.** Stop the server, add the span
setting (the event setting stays `true`), and restart.

**Command:**

```bash
export ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false
adk web --otel_to_cloud ./
```

Ask the London question in a new session. Logs Explorer still shows content in
the `gen_ai.*` events. In Trace Explorer the `call_llm` span's `llm_request` /
`llm_response` attributes are now `{}`.

> [!IMPORTANT]
> **What it means.** Two independent settings.
> `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` governs the log events;
> `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS` governs the span attributes. A
> production setup can keep spans clean while logging content, or the reverse.
> 5.6 is the reference.

**Step 7 — Switch to the experimental semantic convention.** A semantic
convention is OpenTelemetry's naming scheme for GenAI telemetry. The default
format writes separate `gen_ai.system.message`, `gen_ai.user.message`, and
`gen_ai.choice` events; the experimental one, selected by
`OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental`, writes one
`gen_ai.client.inference.operation.details` event per model call. The Agent
Runtime docs use it. Stop the server, add the opt-in, set content back to
`NO_CONTENT` so only the format changes, and restart.

**Command:**

```bash
export OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental
export OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=NO_CONTENT
adk web --otel_to_cloud ./
```

Ask the London question in a new session and run the query again. Instead of
eight split logs you get one `gen_ai.client.inference.operation.details` entry
per `call_llm` span, two for the turn.

**Expected output** (one consolidated event, content off, metadata in `labels`):

```console
{
  "resource": {
    "type": "generic_node",
    "labels": { "project_id": "jwd-gcp-demos", "location": "us-central1", "namespace": "", "node_id": "" }
  },
  "labels": {
    "event.name": "gen_ai.client.inference.operation.details",
    "gen_ai.agent.name": "weather_agent",
    "gen_ai.conversation.id": "dc14be27-393e-4126-a304-16860701713e",
    "gcp.vertex.agent.invocation_id": "e-c290004b-ae01-4baf-9561-26e51abf80fe",
    "gcp.vertex.agent.event_id": "e2a2cd65-b110-4092-a9d7-a8ce9a101927",
    "gen_ai.usage.input_tokens": "229",
    "gen_ai.usage.output_tokens": "15",
    "gen_ai.response.finish_reasons": "[\"stop\"]",
    "gen_ai.tool.definitions": "[{\"name\":\"get_weather\",\"description\":\"Return the current weather for a city.\\n\\nArgs:\\n  city: The city to look up, for example \\\"San Francisco\\\".\\n\\nReturns:\\n  A dict with a ``status`` and either a ``report`` or an ``error_message``.\",\"parameters\":null,\"type\":\"function\"}]"
  },
  "logName": "projects/jwd-gcp-demos/logs/gen_ai.client.inference.operation.details",
  "trace": "projects/jwd-gcp-demos/traces/3b80ad2b7b2b996092831043a1611f4d",
  "spanId": "849de272916dd81f"
}
```

> [!IMPORTANT]
> **What you are looking at.** No `jsonPayload` at all. Everything is in
> `labels`, and none of it is message content.
>
> | Field | Value here | What it is |
> |---|---|---|
> | `event.name` | `gen_ai.client.inference.operation.details` | one consolidated inference event per model call |
> | `gen_ai.usage.input_tokens` / `output_tokens` | `229` / `15` | token counts for this call |
> | `gen_ai.response.finish_reasons` | `["stop"]` | how the model stopped |
> | `gen_ai.tool.definitions` | the `get_weather` schema | the tools the model was offered |
> | `trace` / `spanId` | `…3b80ad2b…` / `849de272…` | the join key to the `call_llm` span |
> | *(message content)* | **absent** | `NO_CONTENT`: usage and shape, nothing said |

**Step 8 — Turn content on under the experimental convention.** Stop the
server, set the event setting to `EVENT_ONLY`, and restart.

**Command:**

```bash
export OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=EVENT_ONLY
adk web --otel_to_cloud ./
```

Ask the London question in a new session and expand the newest
`gen_ai.client.inference.operation.details` entry.

**Expected output** (the final model call, content now in `labels`):

```console
{
  "labels": {
    "event.name": "gen_ai.client.inference.operation.details",
    "gen_ai.agent.name": "weather_agent",
    "gen_ai.usage.input_tokens": "229",
    "gen_ai.usage.output_tokens": "15",
    "gen_ai.response.finish_reasons": "[\"stop\"]",
    "gen_ai.system_instructions": "[{\"content\":\"You are a concise weather assistant. ...\",\"type\":\"text\"}]",
    "gen_ai.input.messages": "[{\"role\":\"user\",\"parts\":[{\"content\":\"What's the weather in London?\\n\",\"type\":\"text\"}]},{\"role\":\"assistant\",\"parts\":[{\"arguments\":{\"city\":\"London\"},\"name\":\"get_weather\",\"id\":\"call_397575\",\"type\":\"tool_call\"}]},{\"role\":\"user\",\"parts\":[{\"response\":{\"status\":\"ok\",\"report\":\"The weather in London is 15C and drizzling.\"},\"id\":\"call_397575\",\"type\":\"tool_call_response\"}]}]",
    "gen_ai.output.messages": "[{\"role\":\"assistant\",\"parts\":[{\"content\":\"The weather in London is currently 15\\u00b0C and drizzling.\",\"type\":\"text\"}],\"finish_reason\":\"stop\"}]"
  },
  "logName": "projects/jwd-gcp-demos/logs/gen_ai.client.inference.operation.details",
  "trace": "projects/jwd-gcp-demos/traces/acacdad756293b70e0b9b8eef517d0ad",
  "spanId": "526c426af55360ea"
}
```

> [!IMPORTANT]
> **What it means.** `EVENT_ONLY` adds three labels: `gen_ai.system_instructions`
> (the system prompt), `gen_ai.input.messages` (everything the model saw this
> call: the question, the `get_weather` call, and the tool's response, as one JSON
> array), and `gen_ai.output.messages` (the reply with its `finish_reason`). They
> are JSON strings in `labels`; the experimental convention never uses
> `jsonPayload`. The production caution from Step 4 applies.

**Step 9 — Clear the shell.** Stop the server, then clear the exports so they do
not leak into 5.3.

**Command:**

```bash
unset OTEL_RESOURCE_ATTRIBUTES
unset OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT
unset ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS
unset OTEL_SEMCONV_STABILITY_OPT_IN
```

5.3 puts the same flag on `adk api_server`: curl in, Cloud Logging out.

## Deep dives

### What does the otel-gcp extra add?

With the flag on, ADK tries to import Google's GenAI SDK instrumentor and
activate it (`cli/api_server.py:738-750`). Installed without the extra, startup
logs one line and carries on:

```console
2026-09-04 17:20:58,660 - WARNING - api_server.py:747 - Unable to import GoogleGenAiSdkInstrumentor - some telemetry will be disabled. Make sure to install google-adk[otel-gcp]
```

`requirements.txt` installs `google-adk[otel-gcp]`, so you should not see it. If
you do, `pip install "google-adk[otel-gcp]==2.8.0"` is the fix. The extra supplies the
`opentelemetry-instrumentation-google-genai` instrumentor, which creates the
`generate_content` spans and the client token metrics. On a laptop its `httpx`
and gRPC companions stay off; ADK activates them only under
`GOOGLE_CLOUD_AGENT_ENGINE_ID` (`cli/api_server.py:751-767`).
