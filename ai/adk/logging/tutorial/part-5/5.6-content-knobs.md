# 5.6 · The content knobs, as reference

*Part 5 · OpenTelemetry*

> [!NOTE]
> **Why you are here.** 5.2 demonstrated the content knobs one step at a time.
> This is the reference: which knob governs which stream, the safe value, and
> how to turn content on deliberately. Nothing runs here.

**Two independent knobs.** Prompt and reply text can ride on the **spans** and on
the **log events**, and each has its own switch (5.2 Step 6 proved they do not
affect each other).

| Stream | Knob | Default | Turn content ON with | ADK source |
|---|---|---|---|---|
| **Log events** (`gen_ai.*`) | `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` | `NO_CONTENT` | `EVENT_ONLY` (or `SPAN_ONLY` / `SPAN_AND_EVENT`) | `telemetry/context.py:93-105` |
| **Span attributes** (`gcp.vertex.agent.llm_request` / `_response`) | `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS` | `true` (content ON) | on by default; set `false` to turn it OFF | `telemetry/context.py:107-113` |

The event knob defaults to **off** and you opt in; the span knob defaults to
**on** and you opt out. Which value turns event content on depends on who emits
the events. With the CLI flag, the `opentelemetry-instrumentation-google-genai`
library emits them and reads the setting itself: the default format takes
`true`, and the experimental format takes `EVENT_ONLY`, `SPAN_ONLY`, or
`SPAN_AND_EVENT` (a `true` there logs a warning and falls back to
`NO_CONTENT`). On your own server (5.5), ADK reads it and also accepts `true`
(`telemetry/context.py:94-101`).

**Both knobs are read per turn, not at import.** Each invocation builds a
`TelemetryConfig` that reads them (`telemetry/tracing.py:865-873`,
`telemetry/context.py:179-180`), so a value set before the next turn takes
effect for that turn, including one in `demo_agent/.env` if you created it. The
endpoint variables (5.2) cannot come from `.env` because the endpoint is chosen
once at server construction; the content knobs are read on every turn.

**Per-request scoping.** A multi-tenant host that must decide content capture
per request sets `RunConfig.telemetry` to a `TelemetryConfig` for one run. It
overrides the env vars for that run and falls back to them otherwise
(`agents/run_config.py:249-255`). It does not reach the `generate_content` span
when the `opentelemetry-instrumentation-google-genai` library emits it (see
"Limitations" in the `TelemetryConfig` docstring in `telemetry/context.py`).

Agent Runtime deploys choose one of these defaults for you; see 6.1.
