# 5.5 · Your own server: install the exporters yourself

*Part 5 · OpenTelemetry*

> [!NOTE]
> **Why you are here.** In 5.1-5.4 the ADK CLI started the process and installed
> the Cloud exporters. Your own server (Part 4) has no CLI, so the `gen_ai.*`
> events are produced but never leave the process. This section adds the two
> lines that send them to Cloud Logging.

**The two calls.** Build the Cloud Logging exporter, then register it, the same
shape the [ADK logging docs](https://adk.dev/observability/logging/#gcp-export-setup_1)
show. In [examples/08_otel_server.py](../../examples/08_otel_server.py) they run
in the `lifespan`, before the `Runner` is built:

```python
from google.adk.telemetry.google_cloud import get_gcp_exporters
from google.adk.telemetry.setup import maybe_set_otel_providers

os.environ.setdefault("OTEL_SERVICE_NAME", "weather-agent")
hooks = get_gcp_exporters(enable_cloud_logging=True)
maybe_set_otel_providers([hooks])
```

`get_gcp_exporters` reads the project and credentials from ADC. This exports
log events only; spans need `enable_cloud_tracing=True`, so the entries below
carry no `trace` or `spanId`. Unlike 5.2, every `OTEL_*` variable can live in
`.env` here, because the server calls `bootstrap()` (which loads `.env`,
`examples/_common.py:49-55`) before it builds the exporters.

**Step 1 — Set two lines in the root `.env`.** The server loads the tutorial
root's `.env` (`ai/adk/logging/.env`, the one beside `env.sh`). Add these two
lines to it. `service.instance.id` makes the entries land on a `generic_task`
resource whose `job` is your `OTEL_SERVICE_NAME`; without it they land on
`generic_node`, which has no `job`. `true` turns event content on.

```
OTEL_RESOURCE_ATTRIBUTES=service.instance.id=laptop-1
OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true
```

**Step 2 — Run the server and send one turn.** A leftover shell export of the
content setting from 5.2 would beat `.env`, so clear it first.

**Command:**

```bash
unset OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT
.venv/bin/python examples/08_otel_server.py
```

**Command** (second terminal):

```bash
curl -s \
  -X POST localhost:8080/chat \
  -H 'content-type: application/json' \
  -d '{"message": "What'\''s the weather in London?"}'
```

**Expected output:**

```console
{"response":"The current weather in London is 15°C and drizzling."}
```

**Step 3 — Read the events back.** In **Logs Explorer**, run the 5.2 query in
the **Query editor**:

**Query:**

```
logName=~"gen_ai\."
```

**Expected output** (eight entries in the default format; one `gen_ai.choice`,
with its `parts` trimmed to the text):

```console
{
  "jsonPayload": {
    "content": {
      "parts": [
        {
          "text": "The current weather in London is 15\u00b0C and drizzling.",
          ...
        }
      ],
      "role": "model"
    },
    "finish_reason": "STOP",
    "index": 0
  },
  "resource": {
    "labels": {
      "job": "weather-agent",
      "location": "global",
      "namespace": "",
      "project_id": "<your-project>",
      "task_id": "laptop-1"
    },
    "type": "generic_task"
  },
  "labels": {
    "event.name": "gen_ai.choice",
    "gen_ai.system": "vertex_ai"
  },
  "logName": "projects/<your-project>/logs/gen_ai.choice"
}
```

> [!IMPORTANT]
> **What it means.** The same `gen_ai.*` events from 5.2-5.4, from a server you
> wrote. `resource.labels.job="weather-agent"` filters to this server, and the
> content is there because Step 1 set it to `true`.

**Step 4 — Set the content setting in `.env`.** In the root `.env`, change the
content line to `NO_CONTENT` and opt in to the experimental event format, so
the two lines read:

```
OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=NO_CONTENT
OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental
```

Stop the server with Ctrl-C in terminal 1, restart it with the Step 2 command,
send the same turn, and run the query again.

**Expected output** (two entries, one per model call; one, trimmed to its
`labels` without `gen_ai.tool.definitions`):

```console
{
  "jsonPayload": null,
  "labels": {
    "event.name": "gen_ai.client.inference.operation.details",
    "gcp.vertex.agent.event_id": "5fc0c92b-223d-4689-9f92-a97100b59ae6",
    "gcp.vertex.agent.invocation_id": "e-18bb88a3-5882-477d-a9b4-b328501c6ea8",
    "gen_ai.agent.name": "weather_agent",
    "gen_ai.conversation.id": "377c95af-faa5-478f-be64-c46e1d6b819f",
    "gen_ai.response.finish_reasons": "[\"stop\"]",
    "gen_ai.usage.input_tokens": "229",
    "gen_ai.usage.output_tokens": "85",
    "gen_ai.usage.reasoning.output_tokens": "70"
  },
  "logName": "projects/<your-project>/logs/gen_ai.client.inference.operation.details"
}
```

> [!IMPORTANT]
> **What it means.** Each entry is now one
> `gen_ai.client.inference.operation.details` event with no
> `gen_ai.input.messages` or `gen_ai.output.messages` field, with no code change
> and no shell export. `NO_CONTENT` is the production default; leave it there
> unless you have a reviewed reason (5.6). Remove the four lines from `.env`
> when you finish this page.

**Step 5 — Deploy the same server to Cloud Run.** The container runs
`python examples/08_otel_server.py` with no change to its code.
[deploy/deploy_otel_server.sh](../../deploy/deploy_otel_server.sh) copies
[deploy/Dockerfile.otel_server](../../deploy/Dockerfile.otel_server) to
`./Dockerfile` for the build and removes it on exit. The image bakes no `.env`,
so the script passes the content setting and the experimental opt-in in
`--set-env-vars`.

**Command:**

```bash
source env.sh
./deploy/deploy_otel_server.sh
```

**Step 6 — Send a turn and read the events back.**

**Command:**

```bash
export URL=$(gcloud run services describe adk-otel-server \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --format='value(status.url)')
curl -s \
  -X POST "$URL/chat" \
  -H 'content-type: application/json' \
  -d '{"message": "What'\''s the weather in London?"}'
```

Run the Step 3 query again.

**Expected output** (one entry, trimmed to its resource and three labels):

```console
{
  "resource": {
    "labels": {
      "location": "global",
      "namespace": "",
      "node_id": "",
      "project_id": "<your-project>"
    },
    "type": "generic_node"
  },
  "labels": {
    "event.name": "gen_ai.client.inference.operation.details",
    "gen_ai.agent.name": "weather_agent",
    "gen_ai.usage.input_tokens": "228"
  },
  "logName": "projects/<your-project>/logs/gen_ai.client.inference.operation.details"
}
```

> [!IMPORTANT]
> **What it means.** The events arrive from Cloud Run, on `generic_node` with no
> `job` label: this path does not detect Cloud Run (`telemetry/setup.py:117-122`),
> and the deploy sets no `service.instance.id`. Filter on
> `labels."gen_ai.agent.name"` instead.

**Step 7 — Tear down.**

**Command:**

```bash
gcloud run services delete adk-otel-server \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --quiet
```

To point the same server at a non-Google OTLP backend, only the exporter
changes. 5.7 has the snippet and the env-var table.
