# 5.3 · The same flag on `adk api_server`

*Part 5 · OpenTelemetry*

> [!NOTE]
> **Why you are here.** `adk api_server` is the headless twin of `adk web`: no
> Trace tab, no `/dev` debug routes, the same telemetry. This section is curl
> in, Cloud Logging out.

Both commands share one option group (`fast_api_common_options`) and build the
server through the same `ApiServer.get_fast_api_app`, where `_setup_telemetry`
runs (`cli/api_server.py:1173`). The flag takes the identical branch 5.2 took.

**Step 1 — Export the three variables (terminal 1), before starting the server.**

**Command:**

```bash
source env.sh
export OTEL_RESOURCE_ATTRIBUTES="service.instance.id=laptop-1,cloud.region=us-central1"
export OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental
export OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=NO_CONTENT
```

| Variable | Why |
|---|---|
| `OTEL_RESOURCE_ATTRIBUTES` | Without it every metrics batch is rejected with a 400 (5.2). |
| `OTEL_SEMCONV_STABILITY_OPT_IN` | Matches 5.2 Step 7 and the Agent Runtime docs. |
| `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` | `NO_CONTENT` is the default and the production value; set explicitly because 5.2 turned it on. |

**Step 2 — Start the API server (terminal 1).**

**Command:**

```bash
adk api_server --otel_to_cloud ./
```

**Step 3 — Send one turn (terminal 2).** The same session-create-then-`/run`
pair as 1.3, on a fresh session.

**Command:**

```bash
curl -s \
  -X POST localhost:8000/apps/demo_agent/users/u1/sessions/s5-api \
  -H 'content-type: application/json' \
  -d '{}'
```

```bash
curl -s \
  -X POST localhost:8000/run \
  -H 'content-type: application/json' \
  -d '{"app_name":"demo_agent","user_id":"u1","session_id":"s5-api",
       "new_message":{"role":"user","parts":[{"text":"What'\''s the weather in London?"}]}}'
```

The `/run` call returns the event list and terminal 1 prints the same INFO
lines as 5.2.

**Step 4 — Read the events back.** In **Logs Explorer**, run the 5.2 query in
the **Query editor**:

**Query:**

```
logName=~"gen_ai\."
```

**Expected output** (two entries, one per `call_llm` span; the second, trimmed
to its `labels` without `gen_ai.tool.definitions`):

```console
{
  "labels": {
    "event.name": "gen_ai.client.inference.operation.details",
    "gcp.vertex.agent.event_id": "e8930251-b52e-44b2-b883-87cb7b79ff7e",
    "gcp.vertex.agent.invocation_id": "e-8d81cab1-104c-4400-8ab1-455c899566c0",
    "gen_ai.agent.name": "weather_agent",
    "gen_ai.conversation.id": "s5-api",
    "gen_ai.response.finish_reasons": "[\"stop\"]",
    "gen_ai.usage.input_tokens": "225",
    "gen_ai.usage.output_tokens": "15"
  },
  "logName": "projects/<your-project>/logs/gen_ai.client.inference.operation.details",
  "trace": "projects/<your-project>/traces/e79a1e3aba6b4f025bd753b42ca9eb82",
  "spanId": "3f3e9c938d0d21db"
}
```

> [!IMPORTANT]
> **What it means.** The entries match 5.2 Step 7: one
> `gen_ai.client.inference.operation.details` per `call_llm` span, content off,
> metadata in `labels`. `gen_ai.conversation.id` is the session id you created.
> The headless server and the dev UI export identical telemetry.

**Step 5 — Clear the shell.** Stop the server (Ctrl-C in terminal 1), then
clear the three exports.

**Command:**

```bash
unset OTEL_RESOURCE_ATTRIBUTES
unset OTEL_SEMCONV_STABILITY_OPT_IN
unset OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT
```

5.4 ships the same flag to Cloud Run, where the process runs under a service
account instead of your ADC login.
