# 3.4 · DebugLoggingPlugin on Cloud Run

*Part 3 · Plugins*

> [!NOTE]
> **Optional. Why you are here.** `DebugLoggingPlugin` writes a file, and a
> Cloud Run container's disk does not outlive it. Running it once on Cloud Run
> teaches a lesson about file-writing tools in ephemeral containers.

A Cloud Run Job's disk is discarded when the execution ends, so a file at
`/app/adk_debug.yaml` vanishes with the container. Cloud Run can mount a Cloud
Storage bucket as a volume instead, and example 04 already reads its output path
from `DEBUG_OUTPUT`.

**Step 1 — Deploy with a bucket mounted, then read the file back.**

The deploy script reads two settings from variables, which you unset afterward.
With `MOUNT=1` it creates `gs://$BUCKET` if it does not exist, mounts it at
`/mnt/out`, and sets `DEBUG_OUTPUT=/mnt/out/adk_debug.yaml` on the Job. `BUCKET`
comes from `env.sh`.

**Command:**

```bash
source env.sh
export MOUNT=1
export SCRIPT=examples/04_debug_plugin.py
./deploy/deploy_plugin_job.sh
unset MOUNT SCRIPT
gcloud storage cat "gs://$BUCKET/adk_debug.yaml" | head -12
```

**Expected output** (the same YAML document as 3.3, read back from the bucket):

```console
---
invocation_id: e-2b6e65a5-6c3d-4a2e-b97d-dedf3396ddeb
session_id: 84bac3fa-b1e7-40ef-abb4-19e05f0abb3e
app_name: debug_plugin_demo
user_id: u1
start_time: '2026-10-03T02:49:25.733100'
entries:
- timestamp: '2026-10-03T02:49:25.733126'
  entry_type: invocation_start
  invocation_id: e-2b6e65a5-6c3d-4a2e-b97d-dedf3396ddeb
  agent_name: weather_agent
  data:
```

**Step 2 — Read the plugin's own lines from Cloud Logging.**

**Command:**

```bash
gcloud logging read \
  'resource.type="cloud_run_job" resource.labels.job_name="adk-debug-plugin-job"
   textPayload:"debug_logging_plugin"' \
  --project="$PROJECT_ID" \
  --limit=10 \
  --format='value(severity,textPayload)' \
  --freshness=15m
```

**Expected output:**

```console
	WARNING - google_adk.google.adk.plugins.debug_logging_plugin - Debug output file /mnt/out/adk_debug.yaml is readable beyond its owner and holds whole prompts and responses; restrict it to mode 600.
	WARNING - google_adk.google.adk.plugins.debug_logging_plugin - No debug state for invocation e-2b6e65a5-6c3d-4a2e-b97d-dedf3396ddeb, skipping entry
	INFO - google_adk.google.adk.plugins.plugin_manager - Plugin 'debug_logging_plugin' registered.
```

> [!IMPORTANT]
> **What it means.** The plugin behaved as on your laptop; only the disk changed.
> The Cloud Storage volume mount reports a mode wider than `0600`, so the plugin
> warns, through `logging`, on stderr. The second warning is the missing
> user-message entry from 3.3. The capture now lives in a bucket and still holds
> full prompts, so access to the bucket now protects the file. If you run it
> routinely in the cloud, you want Part 4's structured plugin instead.

> [!TIP]
> If you need the capture once and do not want a bucket, have the script `cat`
> the file to stdout at the end. It lands in Cloud Logging as one entry per line,
> which you would have to stitch back together, at the cost of the
> one-file-per-run property that made the plugin worth using.

**Step 3 — Tear down.** Delete the Job, then the bucket and the capture it holds.

**Command:**

```bash
gcloud run jobs delete adk-debug-plugin-job \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --quiet
gcloud storage rm --recursive "gs://$BUCKET"
```
