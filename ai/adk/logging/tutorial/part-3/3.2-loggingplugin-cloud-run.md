# 3.2 · LoggingPlugin on Cloud Run

*Part 3 · Plugins*

> [!NOTE]
> **Optional. Why you are here.** You would not deploy `LoggingPlugin` to a real
> service. This section runs it as a Cloud Run Job anyway, so the 3.1 catch
> becomes evidence instead of a claim.

[deploy/deploy_plugin_job.sh](../../deploy/deploy_plugin_job.sh) builds one image
that can run either plugin example. The script is the Job argument and
`LOG_LEVEL` is an environment variable, so you can change the framework level
between runs without rebuilding. Example 03 configures no logging, but
`demo_agent` applies `LOG_LEVEL` to the root and `google_adk` loggers, so it
controls your tool's lines (stream 1) and the framework (stream 2), never the
plugin.

**Step 1 — Deploy and run once at INFO, then run again at WARNING.**

The script deploys the Job and runs it once at INFO; it reads the example to run
from `SCRIPT`, which you unset afterward.

**Command:**

```bash
source env.sh
export SCRIPT=examples/03_logging_plugin.py
./deploy/deploy_plugin_job.sh
unset SCRIPT
gcloud run jobs execute adk-plugin-job \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --update-env-vars=LOG_LEVEL=WARNING \
  --wait
```

Two reads, each selecting lines by a substring. First the framework's lines.

**Command:**

```bash
gcloud logging read \
  'resource.type="cloud_run_job" resource.labels.job_name="adk-plugin-job"
   textPayload:"google_adk"' \
  --project="$PROJECT_ID" \
  --limit=10 \
  --format='value(severity,textPayload)' \
  --freshness=15m
```

**Expected output** (rows for the INFO run, nothing for the WARNING run):

```console
	INFO - google_adk.google.adk.runners - Runner closed.
	INFO - google_adk.google.adk.runners - Closing runner...
	INFO - google_adk.google.adk.models.google_llm - Response received from the model.
	INFO - google_adk.google.adk.models.google_llm - Sending out request, model: gemini-3.7-flash, backend: GoogleLLMVariant.VERTEX_AI, stream: False
	INFO - google_adk.google.adk.models.google_llm - Response received from the model.
	INFO - google_adk.google.adk.models.google_llm - Sending out request, model: gemini-3.7-flash, backend: GoogleLLMVariant.VERTEX_AI, stream: False
	INFO - google_adk.google.adk.plugins.plugin_manager - Plugin 'logging_plugin' registered.
```

> [!IMPORTANT]
> **What it means, finding one: the plugin is independent of the level dial.**
> `LOG_LEVEL=WARNING` removed the framework's lines but, as the next read shows,
> left the plugin narration intact, because the plugin never goes through
> `logging`. That is what makes it useful in development and wrong in production:
> you cannot turn it down without deleting it from the code.

Now the plugin's own lines. This substring also catches the framework's
`Plugin 'logging_plugin' registered.` line.

**Command:**

```bash
gcloud logging read \
  'resource.type="cloud_run_job" resource.labels.job_name="adk-plugin-job"
   textPayload:"logging_plugin"' \
  --project="$PROJECT_ID" \
  --limit=10 \
  --format='value(severity,textPayload)' \
  --freshness=15m
```

**Expected output** (newest first, trimmed to four of the ten): plugin lines with
blank severity and the terminal color codes in the payload, shown here as `^[`.
Each run emits 64 plugin lines, so `--limit=10` returns only the end of the
WARNING run:

```console
	^[[90m[logging_plugin]    Final Agent: weather_agent^[[0m
	^[[90m[logging_plugin]    Invocation ID: e-cf497ad8-ff18-4a6d-9073-6fe1aa5b103d^[[0m
	^[[90m[logging_plugin] ✅ INVOCATION COMPLETED^[[0m
	^[[90m[logging_plugin]    Invocation ID: e-cf497ad8-ff18-4a6d-9073-6fe1aa5b103d^[[0m
```

> [!IMPORTANT]
> **What it means, finding two: the narration is not queryable.** Every plugin
> line lands on stdout with Default severity and grey ANSI codes embedded in the
> text. Nothing in it is a field you can filter, alert on, or group. (The
> `google_adk` lines also land with Default severity, as in 1.4.) These reads
> match a substring with `textPayload:` because nothing here is a real field;
> Part 4 feeds the same hook data through `logging` instead of `print()`.

**Step 2 — Tear down.**

**Command:**

```bash
gcloud run jobs delete adk-plugin-job \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --quiet
```

3.3 turns to `DebugLoggingPlugin`, which writes a whole turn to a file.
