# 1.5 · The same logging behind a real HTTP server

*Part 1 · The log level*

> [!NOTE]
> **Why you are here.** A real service stays up and takes requests, which adds
> the one stream a script never has: the web server's access log (stream 3).
> This page deploys the smallest ADK HTTP server, one that does nothing special
> about logging, so you can see streams 1 to 3 land together.

[examples/09_min_api.py](../../examples/09_min_api.py) is that server: a small
FastAPI app that reads the level from a `LOG_LEVEL` environment variable and
takes control of no stream, on purpose. See
[How is the server composed?](#how-is-the-server-composed)

**Step 1 — Deploy two copies, one at each level.**

The second deploy reads its service name and level from two variables, which
you unset afterward.

**Command:**

```bash
source env.sh
./deploy/deploy_api.sh
export SERVICE=adk-logging-api-warn
export LOG_LEVEL=warning
./deploy/deploy_api.sh
unset SERVICE LOG_LEVEL
```

**Step 2 — Send the same question to each.**

**Command:**

```bash
API_URL=$(gcloud run services describe adk-logging-api \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --format='value(status.url)')
API_URL_W=$(gcloud run services describe adk-logging-api-warn \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --format='value(status.url)')

curl -s \
  -X POST "$API_URL/chat" \
  -H 'content-type: application/json' \
  -d '{"message":"What'\''s the weather in Tokyo?"}'
curl -s \
  -X POST "$API_URL_W/chat" \
  -H 'content-type: application/json' \
  -d '{"message":"What'\''s the weather in Tokyo?"}'
```

**Step 3 — Read the INFO service's logs.**

**Command:**

**Command:**


**Expected output** (trimmed to one question):

```console
SEVERITY  TEXT_PAYLOAD
          INFO:     169.254.169.126:3036 - "POST /chat HTTP/1.1" 200 OK
            declaration = tool._get_declaration()
          /usr/local/lib/python3.13/site-packages/google/adk/models/llm_request.py:298: UserWarning: [EXPERIMENTAL] feature FeatureName.JSON_SCHEMA_FOR_FUNC_DECL is enabled.
```

> [!IMPORTANT]
> **What it means.** Three streams interleave in the INFO service, as they did
> on your laptop: your code (`agent.server`, `demo_agent.agent`), `google_adk`,
> and uvicorn's access line. Stream 4 is Part 5. The severity column repeats
> 1.4's finding: every `INFO -` line is Default, not ERROR, even though
> `basicConfig` writes to stderr.
>
> The WARNING service shows the split. `LOG_LEVEL=warning` reached streams 1 and
> 2, so the lifecycle lines vanished. It did not reach uvicorn's access log,
> which uvicorn configures itself. On a busy service that is one access line per
> request, health checks included. Part 2 fixes the access log; Part 4 gives the
> rest of these lines a severity you can query.

**Step 5 — Tear down.**

**Command:**

```bash
gcloud run services delete adk-logging-api \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --quiet
gcloud run services delete adk-logging-api-warn \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --quiet
```

## Deep dives

### How is the server composed?

Four pieces, and only the first touches logging. The point of the example is
that it does the naive thing at each step, so 1.4's findings show up on a real
service.

**1. Logging config at import.** Before FastAPI is built, the module makes the
same two calls as 1.1 (`basicConfig` and `setLevel` on `google_adk`), plus a root
`setLevel`, reading the level from `LOG_LEVEL`:

```python
def configure(level_name: str) -> None:
    level = getattr(logging, level_name.upper(), logging.INFO)
    logging.basicConfig(level=level, format="%(levelname)s - %(name)s - %(message)s")
    logging.getLogger().setLevel(level)
    logging.getLogger("google_adk").setLevel(level)

configure(os.getenv("LOG_LEVEL", "info"))
```

The explicit `setLevel` calls apply the level even if a platform installed a
root handler first, since `basicConfig` adds one only if the root has none.

**2. A `lifespan` that owns one `Runner`.** The runner is built once at startup
and closed at shutdown, stored on `app.state`:

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.runner = InMemoryRunner(agent=root_agent, app_name="min_api")
    logger.info("runner ready")           # the agent.server line you see in the logs
    try:
        yield
    finally:
        await app.state.runner.close()
```

**3. Two routes.** `GET /healthz`, a conventional health endpoint (Cloud Run's
default startup probe only checks that the port is open), and `POST /chat`,
which creates a session, runs one turn, and returns the final text.

**4. `uvicorn.run` with no `log_config`.** This is the deliberate omission:

```python
uvicorn.run(app, host="0.0.0.0", port=port)   # no log_config, on purpose
```

uvicorn installs its own default logging, so the bare `INFO:` access lines from
1.3 appear unchanged. That is stream 3 configuring itself, which is why
`LOG_LEVEL=warning` silences streams 1 and 2 but never the access log.
