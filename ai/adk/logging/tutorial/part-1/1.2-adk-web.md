# 1.2 · The same dial on `adk web`

*Part 1 · The log level*

`adk web` takes a **`--log_level`** flag (and `-v`, shorthand for `--log_level
DEBUG`). It is the same dial as 1.1, reachable from the command line because the
ADK CLI is launching the process. See
[What the flag really does](#what-the-flag-really-does).

Start the dev UI at `INFO` so the output lines up with 1.1.1, open the URL it
prints, pick **demo_agent** from the app dropdown, and send the same question.

**Command:**

```bash
adk web --log_level INFO ./
```

```
What's the weather in Tokyo?
```

Watch the terminal, not the browser. You get the same five-line lifecycle trail
as the script: two `google_llm` round trips with your `tool get_weather called
for city='Tokyo'` line in the middle. Same agent, same level, same logs. Only
the thing driving it changed.

## Deep dives

### What the flag really does

In 1.1 you set the level in Python, with `logging`, the way any Python program
does. That is the real mechanism and the only one that always applies. The
`--log_level` flag belongs to the `adk web` and `adk api_server` commands, not to
your agent and not to the ADK library. All it does is make the same `logging`
calls on your behalf before starting the server. Launch the agent any other way
and the flag does not exist. In Part 4 you write your own server and configure
logging yourself, because no CLI is there to do it for you.
