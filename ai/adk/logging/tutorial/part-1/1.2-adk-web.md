# 1.2 · The same dial on `adk web`

*Part 1 · The log level*

> [!NOTE]
> **Why you are here.** 1.1 set the level in a script. This page sets the same
> level on `adk web`, ADK's dev UI, with a command-line flag.

`adk web` takes a `--log_level` flag (and `-v`, shorthand for `--log_level
DEBUG`). It is the same dial as 1.1, reachable from the command line because the
ADK CLI is launching the process. See
[What does `--log_level` do?](#what-does---log_level-do).

**Step 1 — Start the dev UI at INFO and ask the question.**

**Command:**

```bash
adk web --log_level INFO ./
```

Then, in the browser:

- Open the URL the command prints.
- Pick **demo_agent** from the app dropdown.
- Send this in the chat box:

```
What's the weather in Tokyo?
```

**Expected output** (the terminal, trimmed to the five lifecycle lines):

```console
2026-10-02 19:17:35,951 - INFO - google_llm.py:255 - Sending out request, model: gemini-3.7-flash, backend: GoogleLLMVariant.VERTEX_AI, stream: False
2026-10-02 19:17:38,223 - INFO - google_llm.py:327 - Response received from the model.
2026-10-02 19:17:38,227 - INFO - agent.py:54 - tool get_weather called for city='Tokyo'
2026-10-02 19:17:38,232 - INFO - google_llm.py:255 - Sending out request, model: gemini-3.7-flash, backend: GoogleLLMVariant.VERTEX_AI, stream: False
2026-10-02 19:17:39,911 - INFO - google_llm.py:327 - Response received from the model.
```

> [!IMPORTANT]
> **What it means.** Watch the terminal, not the browser. You get the same
> lifecycle events as the script, in the CLI's timestamped `file:line` format
> (1.3 looks at it): two `google_llm` round trips with your `tool get_weather
> called` line in the middle. Only the thing driving the agent changed.

1.3 runs the same agent under `adk api_server`, the headless version of this
server.

## Deep dives

### What does `--log_level` do?

In 1.1 you set the level in Python, with `logging`, the way any Python program
does. That is the real mechanism and the only one that always applies. The
`--log_level` flag belongs to the `adk web` and `adk api_server` commands, not to
your agent and not to the ADK library. All it does is make the same `logging`
calls on your behalf before starting the server. Launch the agent any other way
and the flag does not exist. In Part 4 you write your own server and configure
logging yourself, because no CLI is there to do it for you.
