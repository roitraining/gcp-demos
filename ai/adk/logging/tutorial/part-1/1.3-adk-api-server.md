# 1.3 · The same dial on `adk api_server`

*Part 1 · The log level*

> [!NOTE]
> **Why you are here.** `adk api_server` is `adk web` without the UI. This page
> drives it over HTTP and shows what `--log_level` does, and does not, silence.

`adk api_server` has no UI, so you drive it with HTTP.

**Step 1 — Start the server (terminal 1).**

**Command:**

```bash
adk api_server --log_level INFO ./
```

**Step 2 — Create a session and send the question (terminal 2).**

**Command:**

```bash
curl -s \
  -X POST localhost:8000/apps/demo_agent/users/u1/sessions/s1 \
  -H 'content-type: application/json' \
  -d '{}'
```

```bash
curl -s \
  -X POST localhost:8000/run \
  -H 'content-type: application/json' \
  -d '{"app_name":"demo_agent","user_id":"u1","session_id":"s1",
       "new_message":{"role":"user","parts":[{"text":"What'\''s the weather in Tokyo?"}]}}'
```

The response is the full JSON event list, one entry per step of the loop. To
pull out only the answer, pipe it through:

```bash
... | python3 -c "import sys,json; print([p['text'] for e in json.load(sys.stdin) for p in (e.get('content') or {}).get('parts',[]) if p.get('text')][-1])"
```

If the session-create call returns `409 Conflict`, that session id already
exists. Sessions persist in `demo_agent/.adk/session.db` across restarts, so use
a new id.

**Step 3 — Check the server terminal.** Note the format, and what sits between
the framework lines.

**Expected output** (trimmed to the two requests):

```console

INFO:     127.0.0.1:60458 - "POST /apps/demo_agent/users/u1/sessions/s1 HTTP/1.1" 200 OK
2026-10-02 19:18:51,911 - INFO - envs.py:83 - Loaded .env file for demo_agent at .../ai/adk/logging/.env
2026-10-02 19:18:51,913 - INFO - agent_loader.py:188 - Found root_agent in demo_agent.agent
2026-10-02 19:18:52,052 - INFO - google_llm.py:255 - Sending out request, model: gemini-3.7-flash, backend: GoogleLLMVariant.VERTEX_AI, stream: False
2026-10-02 19:18:55,184 - INFO - google_llm.py:327 - Response received from the model.
2026-10-02 19:18:55,189 - INFO - agent.py:54 - tool get_weather called for city='Tokyo'
2026-10-02 19:18:55,196 - INFO - google_llm.py:255 - Sending out request, model: gemini-3.7-flash, backend: GoogleLLMVariant.VERTEX_AI, stream: False
2026-10-02 19:18:58,475 - INFO - google_llm.py:327 - Response received from the model.
2026-10-02 19:18:58,498 - INFO - api_server.py:1854 - Generated 3 events in agent run
INFO:     127.0.0.1:60460 - "POST /run HTTP/1.1" 200 OK
```

> [!IMPORTANT]
> **What it means.** Two formats in one terminal. The timestamped lines are
> streams 1 and 2, your tool and the framework, in the ADK CLI's format. The bare
> `INFO:` lines are stream 3, uvicorn's access log, one per HTTP request.

**Step 4 — Turn the dial down.** Stop the server (Ctrl-C). If
`demo_agent/.env` exists and sets `LOG_LEVEL`, remove that line first; the agent
applies it over the flag (`demo_agent/agent.py:29-33`). Then restart at WARNING.

**Command:**

```bash
adk api_server --log_level WARNING ./
```

Send the same two requests as Step 2, with a new session id.

**Command:**

```bash
curl -s \
  -X POST localhost:8000/apps/demo_agent/users/u1/sessions/w1 \
  -H 'content-type: application/json' \
  -d '{}'
```

```bash
curl -s \
  -X POST localhost:8000/run \
  -H 'content-type: application/json' \
  -d '{"app_name":"demo_agent","user_id":"u1","session_id":"w1",
       "new_message":{"role":"user","parts":[{"text":"What'\''s the weather in Tokyo?"}]}}'
```

**Expected output:**

```console
INFO:     Started server process [34433]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     127.0.0.1:60502 - "POST /apps/demo_agent/users/u1/sessions/w1 HTTP/1.1" 200 OK
INFO:     127.0.0.1:60504 - "POST /run HTTP/1.1" 200 OK
```

> [!IMPORTANT]
> **What it means.** Every timestamped line is gone, as 1.1 Step 3 taught you to
> expect. The `INFO:` access lines are still there after you asked for WARNING.
> The flag did not fail: those lines are stream 3, and `--log_level` never
> reaches it. Part 2 is about that.

## Deep dives

### Where do `adk run` logs go?

`adk run` (the terminal REPL) does not print framework logs to your screen. It
redirects them to a temp file and clears the console handlers. To follow them:

**Command:**

```bash
tail -F "${TMPDIR:-/tmp}/agents_log/agent.latest.log"
```
