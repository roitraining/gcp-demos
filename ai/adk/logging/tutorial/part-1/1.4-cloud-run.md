# 1.4 · The same script on Cloud Run, and what Cloud Logging does to it

*Part 1 · The log level*

> [!NOTE]
> **Why you are here.** Once you deploy, Cloud Logging reads each line and
> assigns it a severity. This page shows that Cloud Run files the unmodified
> Part 1 script's stderr lines as Default severity, not ERROR.

The script runs once and exits, so it deploys as a Cloud Run Job, not a
service. [deploy/deploy_job.sh](../../deploy/deploy_job.sh) builds the image,
deploys the Job, and runs it once at INFO. The level is a Job argument, so you
can rerun at a different level without rebuilding. See
[Why a Job and not a service?](#why-a-job-and-not-a-service) and
[How does the level change per run?](#how-does-the-level-change-per-run)

**Step 1 — Deploy and run at INFO, then run again at WARNING.**

**Command:**

```bash
source env.sh
./deploy/deploy_job.sh
gcloud run jobs execute adk-logging-job \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --args=warning \
  --wait
```

**Step 2 — Read both runs back, with the severity of each line.**

**Command:**

```bash
gcloud logging read \
  'resource.type="cloud_run_job" resource.labels.job_name="adk-logging-job"' \
  --project="$PROJECT_ID" \
  --limit=40 \
  --format='table(severity,textPayload)' \
  --freshness=15m
```

**Expected output** (most recent first; the blank audit-log rows are trimmed):

```console

INFO      Container called exit(0).
          >>> ANSWER: The weather in Tokyo is 27°C and humid.
          ===== running at WARNING =====

INFO      Container called exit(0).
          >>> ANSWER: The weather in Tokyo is currently 27°C and humid.
          ===== running at INFO =====
          INFO - google_adk.google.adk.runners - Runner closed.
          INFO - google_adk.google.adk.runners - Closing runner...
          INFO - google_adk.google.adk.models.google_llm - Response received from the model.
          INFO - google_adk.google.adk.models.google_llm - Sending out request, model: gemini-3.7-flash, backend: GoogleLLMVariant.VERTEX_AI, stream: False
          INFO - demo_agent.agent - tool get_weather called for city='Tokyo'
          INFO - google_adk.google.adk.models.google_llm - Response received from the model.

```

> [!IMPORTANT]
> **What it means, finding one: the level dial works in the cloud, unchanged.**
> The WARNING execution shows the banner, Python's `UserWarning`, and the answer,
> and no `google_adk` or tool lines. The INFO execution carries the lifecycle
> lines from 1.1, read bottom to top. The banner sorts after the stderr lines
> because Python buffers stdout when it is not a terminal and flushes it at
> exit.

> [!IMPORTANT]
> **What it means, finding two: severity is not what you were told.** ADK's own
> source comment (`google/adk/models/lite_llm.py:3002`) says GCP treats stderr
> output as ERROR. `logging.basicConfig` writes to stderr, so every `INFO -`
> line above should read as ERROR. It does not. Every one came through with
> blank (Default) severity. See
> [Are these lines really on stderr?](#are-these-lines-really-on-stderr)

Deploying with no logging changes still delivers your logs, and the level
still controls which ones appear. What you do not get is queryable severity: a
severity-based query or alert cannot tell an error from a routine step. Making
severity a field you set, not a guess Cloud Run makes from the stream, is
Part 4's job.

**Step 3 — Tear down.**

**Command:**

```bash
gcloud run jobs delete adk-logging-job \
  --project="$PROJECT_ID" \
  --region="$REGION" \
  --quiet
```

## Deep dives

### Why a Job and not a service?

The script serves no HTTP. A Cloud Run service would fail its startup check
with no port to probe. A Job runs the container to completion, and Cloud Run
ingests its stdout and stderr into Cloud Logging automatically.

### How does the level change per run?

The deploy sets the fixed environment the container always needs with
`--set-env-vars`: `GOOGLE_GENAI_USE_VERTEXAI`, `GOOGLE_CLOUD_PROJECT`, and
`GOOGLE_CLOUD_LOCATION` (the model region, `global`). None of these is the log
level.

The level is a command-line argument to the script. `01_log_levels.py` reads
`sys.argv[1]`, and `gcloud run jobs execute --args=<level>` overrides the
container's arguments for that one execution, so the image never changes:

```
gcloud run jobs execute ... --args=info      →  python 01_log_levels.py info
gcloud run jobs execute ... --args=warning   →  python 01_log_levels.py warning
```

### Are these lines really on stderr?

Confirm the `INFO -` lines are on stderr, and check their severity again.

**Command:**

```bash
gcloud logging read \
  'resource.type="cloud_run_job" resource.labels.job_name="adk-logging-job"
   textPayload:"get_weather"' \
  --project="$PROJECT_ID" \
  --limit=1 \
  --format='value(logName,textPayload)' \
  --freshness=15m
```

**Expected output:**

```console
projects/<your-project>/logs/run.googleapis.com%2Fstderr	INFO - demo_agent.agent - tool get_weather called for city='Tokyo'
```

The line is on stderr, and its severity is still Default, not ERROR. 1.5 finds
the same result on a Cloud Run service. Do not assume the severity of a plain
line. Check it.
